# 本地 VM 数据库接入说明

> **状态**：✅ 已接入并验证（2026-10-24）
> **背景**：本机 Docker Desktop 暂停使用，数据库与缓存放进本地 VMware 虚拟机的 Docker 里，后端在 Windows 宿主机运行。

---

## 一、拓扑

```
Windows 宿主机                          VMware 虚拟机
┌──────────────────────┐               ┌──────────────────────────────────┐
│ backend (uvicorn:8000)│──5433──────▶│ aiinsight-postgres  (pgvector/pgvector:pg14) │
│ frontend (vite:5173)  │──6379──────▶│ aiinsight-redis     (redis:7-alpine)         │
└──────────────────────┘               └──────────────────────────────────┘
        宿主机网卡 VMnet8: 192.168.150.1/24   VM: 192.168.150.100
```

| 项 | 值 |
|---|---|
| 虚拟机 | VMware Workstation，`Rocky Linux 9.7`，4 vCPU / 8 GB / 62 GB |
| VM 地址 | `192.168.150.100`（VMnet8 NAT） |
| 项目 compose | VM 内 `/root/ai-insight-hub-infra/docker-compose.yml` |
| PostgreSQL | 容器 `aiinsight-postgres`，镜像 `pgvector/pgvector:pg14`，VM 端口 5432 → **宿主 5433** |
| Redis | 容器 `aiinsight-redis`，镜像 `redis:7-alpine`，端口 6379 |
| 库 / 用户 / 密码 | `aiinsight` / `aiinsight` / `dev_password` |
| 扩展 | `vector 0.8.7`、`pg_trgm 1.6`、`pgcrypto 1.3` |

> **为什么 PG 用 5433**：VM 的 5432 已被另一项目容器 `medical_pgvector` 占用，本项目改用 5433 避免冲突，两者互不影响。

## 二、日常操作

登录 VM 后（MobaXterm，`root@192.168.150.100`）：

```bash
cd /root/ai-insight-hub-infra

docker compose ps          # 查看状态
docker compose up -d       # 启动（开机后执行）
docker compose down        # 停止（数据在 named volume 里，不会丢）
docker compose logs -f postgres
```

容器均为 `restart: unless-stopped`，VM 启动后会自动拉起。

宿主机侧验证：

```powershell
# 端口连通
Test-NetConnection 192.168.150.100 -Port 5433
Test-NetConnection 192.168.150.100 -Port 6379

# 应用配置实际连库
cd backend
.\venv\Scripts\python.exe -c "from sqlalchemy import create_engine, text; from app.core.config import settings; print(create_engine(settings.DATABASE_URL).connect().execute(text('select 1')).scalar())"
```

## 四、已知问题

1. **MinIO 未启动**：VM 的 `/etc/docker/daemon.json` 配置了镜像加速 `docker.m.daocloud.io` / `docker.1panel.live`，
   拉 `minio/minio` / `minio/mc` 时返回 `403 Forbidden`，故当前 compose 只含 PG + Redis。
   → 需要对象存储时，换直连源（临时改 `registry-mirrors`）或改用本机/云 S3。**M2 阶段不阻塞。**
2. **VM 上原有服务未动**：`medical_pgvector`(5432)、`elasticsearch-8.4.1`(9200/9300)、`rabbitmq`(5672/15672)、
   以及已退出的 `rmq*` / `dejavu` 容器均保持原状，本次只新增 `aiinsight-*` 两个容器和两个 volume。
3. **VM 防火墙未开**：`firewalld` 为 inactive，宿主可直接访问映射端口。若日后启用 firewalld，需放行 5433/6379
   （或仅放行 `192.168.150.0/24`）。
4. **SELinux 为 Enforcing**：当前挂载 `init_db.sql` 只读文件可正常工作；若后续挂载其它宿主目录报 `Permission denied`，
   需 `chcon`/`:Z` 处理。
5. **Alembic 仍无迁移**：`backend/migrations/versions/` 为空，`alembic upgrade head` 目前是空操作；
   业务表要等 M3 首个迁移落地。

## 五、切换回本机 Docker 的方法

```powershell
# 1) 本机起容器
docker-compose up -d

# 2) 改 backend/.env（这三组）
#    DATABASE_URL=postgresql://aiinsight:dev_password@localhost:5432/aiinsight
#    REDIS_URL=redis://localhost:6379/0
#    CELERY_BROKER_URL=redis://localhost:6379/1
#    CELERY_RESULT_BACKEND=redis://localhost:6379/2

# 3) 可停掉 VM 里的容器
cd /root/ai-insight-hub-infra && docker compose down
```
