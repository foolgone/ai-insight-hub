### 4.1 `vitest.config.js`（推荐，**待新增**）

```js
// frontend/vitest.config.js
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  test: {
    // DOM 环境（需已安装 jsdom）
    environment: 'jsdom',
    // 全局 setup：jest-dom 断言 + matchMedia mock
    setupFiles: ['./src/test/setup.js'],
    // 只跑 src 下的测试
    include: ['src/**/*.{test,spec}.{js,jsx}'],
    // 不在测试里注入 globals，统一显式 import { test, expect, vi }
    globals: false,
    // 清理 mock，避免跨用例污染
    clearMocks: true,
    restoreMocks: true,
    coverage: {
      provider: 'v8',
      reporter: ['text', 'html', 'lcov'],
      reportsDirectory: './coverage',
      include: ['src/**/*.{js,jsx}'],
      exclude: [
        'src/main.jsx',
        'src/test/**',
        'src/**/*.test.{js,jsx}',
        'src/**/*.spec.{js,jsx}',
      ],
      // ⚠️ 键名是 thresholds（不是 coverageThresholds / coverageThreshold）
      thresholds: {
        lines: 80,
        functions: 80,
        statements: 80,
        branches: 70,
      },
    },
  },
});
```

> **为什么不直接写进 `vite.config.js`**：`vite.config.js` 用的是 `defineConfig` from `'vite'`，加入 `test` 字段虽然运行时不报错，但 IDE 会标红；单独 `vitest.config.js` 更清晰。若团队坚持单文件，可把 `test` 块原样搬进 `vite.config.js`（**待确认**，确认方式：前端负责人在首个测试 PR 中定稿）。

### 4.2 全局 setup：`src/test/setup.js`（**待新增**）

```js
// frontend/src/test/setup.js
import '@testing-library/jest-dom/vitest';
import { cleanup } from '@testing-library/react';
import { afterEach, vi } from 'vitest';

// 每个用例后卸载组件，避免 DOM 残留

      matches: false,
      media: query,
      onchange: null,
      addEventListener: vi.fn(),
      removeEventListener: vi.fn(),
      addListener: vi.fn(), // 兼容旧 API

      dispatchEvent: vi.fn(),
```

### 4.3 自定义 render（`src/test/utils.jsx`）

页面级组件依赖 Router 与 React Query，用统一封装避免每个用例重复：

```jsx
// frontend/src/test/utils.jsx
import { render } from '@testing-library/react';
import { MemoryRouter } from 'react-router-dom';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

/**
 * 渲染带 Provider 的组件树。
 * @param {React.ReactElement} ui 被测组件
 * @param {{ route?: string }} [options]
 */
export function renderWithProviders(ui, { route = '/' } = {}) {
  const queryClient = new QueryClient({
    defaultOptions: {
      queries: { retry: false, gcTime: 0 }, // 测试中不重试、不缓存
    },
  });

  return render(
    <QueryClientProvider client={queryClient}>
      <MemoryRouter initialEntries={[route]}>{ui}</MemoryRouter>
    </QueryClientProvider>
  );
}
```

> 注意用 **`gcTime`**（React Query v5），v4 的 `cacheTime` 在 v5 已移除。

#### 4.3.1 路由懒加载预热（`preloadRoutes`）

`router.jsx` 用 `lazy(() => import(...))` 加载页面。全量并行跑测试时，多个 worker 争抢 Vite
模块转换，首次加载较重页面（Dashboard → recharts）可能超过 `findBy*` 超时，导致用例偶发停在
`Suspense` fallback（实测偶发率约 1/2 次全量运行）。

约定：**凡是渲染 `AppRoutes` 的测试文件**，在 `beforeAll` 中预热一次：

```jsx
import { beforeAll } from 'vitest';
import { preloadRoutes, renderWithProviders } from '../utils';

beforeAll(preloadRoutes, 30000);
```

`preloadRoutes()` 会 `Promise.all` 预加载全部 9 个页面模块，后续 `lazy` 命中模块缓存，断言不再依赖
模块转换耗时的波动。新增页面时需同步补充到 `preloadRoutes` 的导入列表。

```jsx
// src/components/Button/Button.test.jsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, expect, it, vi } from 'vitest';
import { Button } from './Button';

describe('Button', () => {
  it('渲染文本', () => {
    render(<Button>点击</Button>);
    expect(screen.getByText('点击')).toBeInTheDocument();
  });

  it('点击触发 onClick', async () => {
    const handleClick = vi.fn();
    const user = userEvent.setup();

    render(<Button onClick={handleClick}>点击</Button>);
    await user.click(screen.getByRole('button'));

    expect(handleClick).toHaveBeenCalledTimes(1);
  });

  it('loading 时禁用且暴露 role=status', () => {
    render(<Button loading>保存</Button>);

    expect(screen.getByRole('button')).toBeDisabled();
    expect(screen.getByRole('status')).toBeInTheDocument();
  });

  it('按变体应用类名', () => {
    const { rerender } = render(<Button variant="primary">主按钮</Button>);
    expect(screen.getByRole('button')).toHaveClass('bg-primary-500');

    rerender(<Button variant="secondary">次按钮</Button>);
    expect(screen.getByRole('button')).toHaveClass('bg-gray-100');
  });

  it('键盘可触发', async () => {
    const handleClick = vi.fn();
    const user = userEvent.setup();

    render(<Button onClick={handleClick}>按钮</Button>);

    await user.tab();
    expect(screen.getByRole('button')).toHaveFocus();

    await user.keyboard('{Enter}');
    expect(handleClick).toHaveBeenCalledTimes(1);
  });
```

## 六、API Mock（`vi.mock` + `vi.fn`，**不使用 MSW**）

### 6.1 原则

| 层 | 做法 | 说明 |
|----|------|------|
| **最常用**：mock 自己的 API 模块 | `vi.mock('../../api/dataSources', ...)` + `vi.fn()` 返回固定数据 | 组件只依赖 `api/*`，不直接 `fetch` |
| 需要验证请求参数 | 断言 `vi.fn()` 的调用参数 | 比拦截网络更直接 |
| 需要模拟网络错误 | `mockRejectedValue(new Error('Network Error'))` | 覆盖错误分支 |
| **不要做** | 不启动真实 HTTP 服务器（MSW 未安装，且无必要） | — |

### 6.2 mock 一个 API 模块

```jsx
// src/pages/DataSources/DataSourcesPage.test.jsx
import { screen, waitFor } from '@testing-library/react';
import { beforeEach, describe, expect, it, vi } from 'vitest';
import { renderWithProviders } from '../../test/utils';
import { DataSourcesPage } from './DataSourcesPage';
import { listDataSources } from '../../api/dataSources';

// 整个模块替换为 mock（不会真的发请求）
vi.mock('../../api/dataSources', () => ({
  listDataSources: vi.fn(),
  createDataSource: vi.fn(),
  deleteDataSource: vi.fn(),
}));

describe('DataSourcesPage', () => {
  beforeEach(() => {
    listDataSources.mockResolvedValue({
      items: [
        { id: '1', name: '客服对话-2026年1月', type: 'customer_service', status: 'active' },
        { id: '2', name: '销售话术-2026年2月', type: 'sales', status: 'processing' },
      ],
      pagination: { page: 1, limit: 20, total: 2, pages: 1, has_next: false, has_prev: false },
    });
  });

  it('加载后展示数据源列表', async () => {
    renderWithProviders(<DataSourcesPage />, { route: '/data-sources' });

    // 加载态
    expect(screen.getByText('加载中...')).toBeInTheDocument();

    // 数据到达
    await waitFor(() => {
      expect(screen.getByText('客服对话-2026年1月')).toBeInTheDocument();
    });
    expect(screen.getByText('销售话术-2026年2月')).toBeInTheDocument();

    // 请求参数断言
    expect(listDataSources).toHaveBeenCalledTimes(1);
  });

  it('请求失败展示错误提示', async () => {
    listDataSources.mockRejectedValueOnce(new Error('Network Error'));

    renderWithProviders(<DataSourcesPage />, { route: '/data-sources' });

    await waitFor(() => {
      expect(screen.getByText('网络连接失败，请重试')).toBeInTheDocument();
    });
  });
});
```

> **接口路径口径**：`/api/v1/datasources`（不是 `data_sources`），`axios` 实例的 `baseURL` 已含 `/api/v1`，因此 `api/dataSources.js` 里写 `/datasources`。mock 层不涉及路径，但**断言 URL 的测试要按此口径写**。

## 八、可访问性测试（手工 + 对比度）

### 8.1 为什么不用 jest-axe

`jest-axe` / `@axe-core/react` / `@axe-core/playwright` **均未安装**，且都是 Jest/浏览器自动化生态。引入会带来额外依赖与版本适配成本，MVP 阶段改用**手工检查清单 + 对比度工具**。

### 8.2 手工检查清单（每个组件/页面 PR 必过）

- [ ] 所有交互元素可用 Tab 到达，焦点顺序符合视觉顺序
- [ ] 焦点可见（`focus:ring-2 focus:ring-primary-500 focus:ring-offset-2`）
- [ ] 图标按钮有 `aria-label`；表单错误有 `aria-invalid` + `aria-errormessage`
- [ ] 弹层（Modal/Drawer）打开时焦点进入、关闭时回到触发按钮，Esc 可关闭
- [ ] 文字对比度 ≥ 4.5:1（大文本/图形 ≥ 3:1）
- [ ] **链接/正文不使用 `primary-500`**（3.68:1 不达标），改用 `primary-600` / `primary-700`
- [ ] 表格有 `<caption>` 或 `aria-label`

### 8.3 能在 Vitest 里自动断言的部分（可测的语义）

```jsx
// src/components/Button/Button.a11y.test.jsx
import { render, screen } from '@testing-library/react';
import { describe, expect, it } from 'vitest';
import { Button } from './Button';

describe('Button 可访问性（语义断言）', () => {
  it('可访问名称为按钮文本', () => {
    render(<Button>点击</Button>);
    expect(screen.getByRole('button', { name: '点击' })).toBeInTheDocument();
  });

  it('加载态暴露 role=status', () => {
    const { container } = render(<Button loading>加载中</Button>);
    expect(container.querySelector('[role="status"]')).not.toBeNull();
  });

  it('禁用态使用原生 disabled', () => {
    render(<Button disabled>禁用</Button>);
    expect(screen.getByRole('button')).toBeDisabled();
  });
});
```

> 对比度**不能**靠 jsdom 断言（无样式计算），必须用 [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) 手工核验并记录在 PR 描述里。

## 九、响应式测试

### 9.1 通过 `matchMedia` mock 验证分支

```jsx
// src/components/Header/Header.test.jsx
import { render, screen } from '@testing-library/react';
import { beforeEach, describe, expect, it, vi } from 'vitest';
import { Header } from './Header';

/**
 * 覆写 matchMedia，让指定查询返回匹配结果。
 * @param {(query: string) => boolean} matcher
 */
function mockMatchMedia(matcher) {
  Object.defineProperty(window, 'matchMedia', {
    writable: true,
    value: vi.fn().mockImplementation((query) => ({
      matches: matcher(query),
      media: query,
      onchange: null,
      addEventListener: vi.fn(),
      removeEventListener: vi.fn(),
      addListener: vi.fn(),
      removeListener: vi.fn(),
      dispatchEvent: vi.fn(),
    })),
  });
}

describe('Header 响应式', () => {
  beforeEach(() => {
    vi.resetAllMocks();
  });

  it('移动端（< 768px）显示汉堡菜单', () => {
    mockMatchMedia((q) => q === '(max-width: 767px)');
    render(<Header />);
    expect(screen.getByLabelText('Menu')).toBeInTheDocument();
  });

  it('桌面端（≥ 1024px）不显示汉堡菜单', () => {
    mockMatchMedia(() => false);
    render(<Header />);
    expect(screen.queryByLabelText('Menu')).not.toBeInTheDocument();
  });
});
```

### 9.2 必测断点（与 `05-design/04-响应式设计规范.md` 一致）

| 视口宽度 | 档位 | 期望 |
|---------|------|------|
| 375px | `xs`（典型值） | 统计卡片 1 列、Sidebar 抽屉、表格卡片化 |
| 768px | `md` | 统计卡片 2 列、Sidebar 折叠 |
| 1024px | `lg` | 统计卡片 4 列、图表 2 列 |
| 1280px | `xl` | Sidebar 固定展开 |

> 布局类断言（列数）**不做**（jsdom 无布局引擎），只断言「分支渲染出哪个组件 / 哪个类名」，视觉结果靠手工截图核对。

## 十四、最佳实践

### 14.1 ✅ 好的测试

- 用**语义查询**（`getByRole` / `getByLabelText` / `getByText`），不用 `container.querySelector('.btn-primary')`
- 用 `userEvent`（真实事件序列）而不是 `fireEvent`（除非测边界）
- 一个用例只验证一个行为；`describe` 按「组件 → 行为」分层
- mock 只 mock 边界（`api/*`、`matchMedia`、`toast`），不 mock 被测组件内部
- 断言 class 时只断言**语义化 token 类名**（`bg-primary-500`），不断言 `p-4 mt-2` 这类布局细节

### 14.2 ❌ 差的测试

- 用 Jest API（`jest.fn()`、`jest.mock()`）→ Vitest 里**必须**用 `vi.fn()` / `vi.mock()`
- 断言完整 DOM 快照（一改样式就红，维护成本极高）
- 用例之间共享可变 mock 状态（用 `clearMocks` / `restoreMocks` 隔离）
- 在测试里 `await new Promise(r => setTimeout(r, 500))` 硬等（用 `waitFor` / `findBy*`）

### 14.3 常见坑

| 现象 | 原因 | 解法 |
|------|------|------|
| `toHaveBeenCalledTimes` 不存在 | 未加载 jest-dom | `setupFiles` 里 `import '@testing-library/jest-dom/vitest'` |
| `matchMedia is not a function` | jsdom 未实现 | setup 里 mock（见 4.2） |
| `useNavigate() may be used only in the context of a <Router>` | 组件用了路由 | 用 `renderWithProviders`（MemoryRouter） |
| 查询「加载中」失败 | React Query 立刻 resolve | 用 `waitFor`，或在 mock 里加 `await Promise.resolve()` 制造一帧延迟 |
| `Cannot find package 'jsdom'` | 未安装 | `npm i -D jsdom` |
