## 二、通用规范

### 2.1 命名约定

#### 测试文件
- **格式**: `test_<module_name>.py`
- **示例**: `test_cleaning_agent.py`

#### 测试类
- **格式**: `Test<ClassName>`
- **示例**: `TestDataCleaningAgent`

#### 测试函数
- **格式**: `test_<function>_<scenario>_<expected_result>`
- **示例**: `test_parse_dialogue_with_valid_input_returns_dict`

### 2.2 AAA 模式

所有测试遵循 **Arrange-Act-Assert** 模式：

```python
def test_example():
    # Arrange（准备）- 设置测试数据和环境
    agent = DataCleaningAgent()
    input_data = {"raw": "用户: 退款"}
    
    # Act（执行）- 调用被测试的函数
    result = agent.parse(input_data)
    
    # Assert（断言）- 验证结果
    assert result["user_message"] == "退款"
```

### 2.3 测试独立性

- ✅ 每个测试独立运行
- ✅ 测试间无依赖顺序
- ✅ 使用 Fixture 隔离状态
- ❌ 避免共享可变状态

### 3.2 质量评估 Agent

#### 测试覆盖点

质量评估固定为 **5 个维度**，机器可读 key 为 `accuracy` / `completeness` / `tone` / `compliance` / `hallucination`，各维度与总分均为 **0–100**（口径见 [产品概述](../01-requirements/01-产品概述.md)）。

- [x] 5 个维度齐全，缺维度即判失败
- [x] 各维度分值与总分在 0–100 区间（含边界 0 与 100）
- [x] 高质量 / 低质量对话的分档差异
- [x] 维度间矛盾检测（如 `compliance` 高但 `hallucination` 也高）

> 输出字段采用 `_score` 后缀（`accuracy_score` 等），与 [开发规范](../04-development/01-开发规范.md) 的 docstring 约定一致。若实现改为嵌套结构（如 `result["scores"]["accuracy"]`），需同步改用例——**当前以 `_score` 为准**。

#### 测试示例

```python
# tests/unit/test_agents/test_evaluation_agent.py
import pytest
from app.agents.evaluation_agent import QualityEvaluationAgent

class TestQualityEvaluationAgent:
    """质量评估 Agent 测试"""
    
    @pytest.fixture
    def agent(self):
        return QualityEvaluationAgent()
    
    def test_evaluate_high_quality_dialogue_returns_high_score(self, agent):
        """给定高质量对话，评估应返回高分"""
        # Arrange
        dialogue = {
            "user_message": "订单何时发货？",
            "ai_response": "您的订单预计明天发货，物流单号将短信通知。",
            "context": {"order_id": "12345"}
        }
        
        # Act
        result = agent.evaluate(dialogue)
        
        # Assert
        assert result["accuracy_score"] >= 80
        assert result["completeness_score"] >= 80
        assert result["overall_score"] >= 80
    
    def test_evaluate_incomplete_response_returns_low_score(self, agent):
        """给定不完整回复，评估应返回低分"""
        # Arrange
        dialogue = {
            "user_message": "订单何时发货？",
            "ai_response": "好的",  # 没有实质内容
            "context": {}
        }
        
        # Act
        result = agent.evaluate(dialogue)
        
        # Assert
        assert result["completeness_score"] < 50
    
    def test_evaluate_score_range_is_valid(self, agent):
        """5 个维度分值与总分都应在 0-100 范围内"""
        # Arrange
        dialogue = {
            "user_message": "测试",
            "ai_response": "测试回复",
            "context": {}
        }

        # Act
        result = agent.evaluate(dialogue)

        # Assert
        dimension_fields = [
            "accuracy_score",
            "completeness_score",
            "tone_score",
            "compliance_score",
            "hallucination_score",
        ]
        for field in dimension_fields:
            assert field in result, f"缺少维度字段: {field}"
            assert 0 <= result[field] <= 100
        assert 0 <= result["overall_score"] <= 100
```

import pytest
from unittest.mock import patch, Mock
from app.agents.cleaning_agent import DataCleaningAgent

class TestDataCleaningAgentWithMock:

        mock_response.content = '{"user_message": "退款", "ai_response": "请提供订单号"}'
        mock_llm_cls.return_value.invoke.return_value = mock_response

        agent = DataCleaningAgent()

| 作用域 | 说明 | 用途 |

| `function` | 每个测试函数 | 默认，测试间隔离 |

## 十、覆盖率配置

### 10.1 `backend/pytest.ini`（已存在，不要重复创建）

```ini
[pytest]
testpaths = tests
python_files = test_*.py
python_classes = Test*
python_functions = test_*
asyncio_mode = auto
addopts = -q --strict-markers
markers =
    unit: 单元测试（不依赖外部服务）
    integration: 集成测试（需要真实 PostgreSQL/Redis，见 docker-compose.test.yml）
    prompt: Prompt 测试（需要真实 LLM，默认排除：pytest -m "not prompt"）
    slow: 慢速测试
```

要点：

- `testpaths = tests` 是**整个** `tests/`，不单独指向 `tests/unit`——单元与集成共用一份配置，靠 marker 区分
- `--strict-markers` 已开启：使用未注册的 marker（如 `@pytest.mark.performance`）会**直接报错**，需先在 `markers` 中登记
- `asyncio_mode = auto` 已开启：异步测试无需 `@pytest.mark.asyncio`
- 覆盖率参数**不写进 `addopts`**：否则每次运行（包括 `--lf`、单文件调试）都会强制统计并卡阈值，本地调试会很痛苦。覆盖率只在需要时通过命令行传参，CI 中显式传入

### 10.2 `backend/.coveragerc`（✅ 已存在）

`[tool.coverage.*]` **不能**写在 `pytest.ini` 里（pytest 不读取 coverage 的配置节），因此统一放在 `backend/.coveragerc`（已随仓库提供）：

```ini
[run]
source = app
omit =
    */tests/*
    */migrations/*
    */venv/*
    */__pycache__/*
    */config.py

[report]
exclude_lines =
    pragma: no cover
    def __repr__
    raise AssertionError
    raise NotImplementedError
    if __name__ == .__main__.:
    @abstract
```

> 在该文件创建之前，`--cov=app` 会把 `tests/` 之外的 `app/` 全量计入，`config.py` 这类纯配置模块会拉低覆盖率——属于已知偏差，不是测试写得不好。

### 10.3 覆盖率门禁

CI（`.github/workflows/test.yml`）中的实际命令：

```bash
pytest -m "not prompt" --cov=app --cov-report=term-missing --cov-fail-under=80
```

本地复现：

```bash
cd backend
pytest -m "not prompt" --cov=app --cov-report=term-missing
pytest tests/unit -m unit --cov=app --cov-report=html
```

| 口径 | 值 | 说明 |
|------|----|------|
| 阈值 | 80% | 单元 + 集成合并计算 |
| 统计范围 | `app/` | 排除规则见 10.2（待生效） |
| 分层目标 | 单元 ≥ 80%、集成 ≥ 60% | 评审目标，非独立门禁 |

## 十三、常见问题

### Q1: 如何测试私有方法？

**A**: 不直接测试私有方法，通过公共接口间接验证。

```python
# ❌ 差：直接测试私有方法
def test_private_method(agent):
    result = agent._internal_parse("data")
    assert result == "parsed"

# ✅ 好：通过公共方法测试
def test_public_method_uses_internal_logic(agent):
    result = agent.parse("data")  # 内部调用 _internal_parse
    assert result == "expected_output"
```

---

### Q2: 如何处理随机性？

**A**: 业务代码的随机性用固定种子或 mock；**LLM 的随机性无法用 seed 消除**（DeepSeek 没有 `seed` 参数），只能靠 `temperature=0` + 结构断言 + 语义相似度。

```python
# 方法 1：业务代码固定种子
import random

def test_with_fixed_seed():
    random.seed(42)
    assert function_using_random() == expected_value

# 方法 2：Mock 随机函数
@patch("module_name.random.randint")
def test_with_mock(mock_randint):
    mock_randint.return_value = 5
    result = function_using_random()
    assert result == expected_value
```

> `@patch` 的目标是**被测模块内引用该函数的位置**（如 `app.services.xxx.random.randint`），直接写 `@patch("random.randint")` 通常不会生效。

---

### Q3: 如何加速慢速测试？

**A**:

1. Mock 外部依赖（LLM、第三方 API）
2. **单元测试层不连库**——不要用 SQLite 顶替 PostgreSQL：本项目依赖 `JSONB`、`vector`、`pg_trgm`，SQLite 都没有，用它会掩盖真实问题
3. 并行运行：`pytest -n auto`（pytest-xdist 3.5.0 已声明）
4. 用 marker 分离：`-m "not slow"`、`-m "not prompt"`

```python
# 标记慢速测试
@pytest.mark.slow
def test_heavy_computation():
    pass
```

```bash
# 运行时排除慢速测试
pytest -m "not slow"

# 排除 Prompt 测试（需真实 LLM）
pytest -m "not prompt"
```
