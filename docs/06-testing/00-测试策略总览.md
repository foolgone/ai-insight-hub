## 一、测试目标

### 1.1 核心目标
- **质量保障**: 确保代码质量和系统稳定性
- **快速反馈**: 尽早发现问题，降低修复成本
- **持续集成**: 支持 CI/CD 自动化流程
- **文档化**: 测试即文档，描述系统行为

### 1.2 覆盖率目标

| 测试类型 | 覆盖率目标 | 执行频率 |
|---------|-----------|---------|
| **单元测试** | ≥ 80% | 每次提交 |
| **集成测试** | ≥ 60% | 每次提交 |
| **E2E 测试** | 关键流程 100% | 每日/部署前 |
| **性能测试** | 核心 API | 每周/部署前 |
| **Prompt 测试** | 每个 Agent ≥ 50 用例 | 每次 Prompt 变更 |

## 二、测试金字塔

### 2.1 测试分层

```
              ┌─────────────────┐
              │   E2E 测试      │  5%   (慢，昂贵，全链路)
              │  关键流程验证    │
              └─────────────────┘
                     ↑
          ┌──────────────────────┐
          │    集成测试           │  25%  (中速，API+DB+Redis)
          │  模块间协作验证       │
          └──────────────────────┘
                     ↑
     ┌────────────────────────────────┐
     │       单元测试                  │  70%  (快，隔离，细粒度)
     │  函数/类级别验证               │
     └────────────────────────────────┘
```

### 2.2 各层职责

#### 单元测试（70%）
- **范围**: 单个函数/类/组件
- **目标**: 逻辑正确性、边界条件、异常处理
- **特点**: 快速、隔离、可重复
- **工具**: pytest（后端）、Jest（前端）

#### 集成测试（25%）
- **范围**: 模块间协作（API + DB + Redis）
- **目标**: 接口契约、数据流转、状态一致性
- **特点**: 依赖真实数据库/缓存
- **工具**: pytest + TestClient、React Testing Library

#### E2E 测试（5%）
- **范围**: 完整业务流程（前端 → 后端 → DB）
- **目标**: 用户场景验证
- **特点**: 慢、脆弱、维护成本高
- **工具**: Playwright

## 三、测试类型详解

### 3.1 后端测试

#### 单元测试
```python
# tests/unit/test_agents/test_cleaning_agent.py
def test_parse_dialogue():
    """测试对话解析逻辑"""
    agent = DataCleaningAgent()
    raw = "用户: 退款怎么办？\nAI: 请提供订单号"
    result = agent.parse_dialogue(raw)
    
    assert result["user_message"] == "退款怎么办？"
    assert result["ai_response"] == "请提供订单号"
```

#### 集成测试
```python
# tests/integration/test_api/test_data_sources.py
def test_create_data_source(client, db_session):
    """测试创建数据源 API"""
    response = client.post("/api/v1/data_sources", json={
        "name": "淘宝店A",
        "platform": "taobao",
        "config": {...}
    })
    
    assert response.status_code == 201
    # 验证数据库写入
    ds = db_session.query(DataSource).first()
    assert ds.name == "淘宝店A"
```

#### Prompt 测试
```python
# tests/prompt/test_cleaning_prompts.py
@pytest.mark.parametrize("input,expected", [
    ("用户: 退款", {"user_message": "退款"}),
    ("AI: 请稍候", {"ai_response": "请稍候"}),
    # 50+ 测试用例
])
def test_cleaning_prompt(input, expected):
    """测试数据清洗 Prompt"""
    agent = DataCleaningAgent()
    result = agent.clean(input)
    assert result["user_message"] == expected["user_message"]
```

### 4.2 测试数据管理

#### 固定数据（Fixtures）
```python
# tests/conftest.py
@pytest.fixture
def sample_dialogue():
    """样例对话数据"""
    return {
        "user_id": "user_001",
        "message": "订单何时发货？",
        "timestamp": "2026-10-24T10:00:00Z"
    }
```

#### 工厂模式
```python
# tests/factories.py
import factory
from app.models import User, DataSource

class UserFactory(factory.Factory):
    class Meta:
        model = User
    
    email = factory.Sequence(lambda n: f'user{n}@example.com')
    name = factory.Faker('name')
```

#### 数据库清理
```python
# tests/conftest.py
@pytest.fixture(autouse=True)
def reset_db(db_session):
    """每个测试后重置数据库"""
    yield
    db_session.rollback()
    db_session.query(DataSource).delete()
    db_session.commit()
```

## 五、CI/CD 集成

### 5.1 GitHub Actions 流程

```yaml
# .github/workflows/test.yml
name: Test

on: [push, pull_request]

jobs:
  backend-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: 启动测试服务
        run: docker-compose -f docker-compose.test.yml up -d
      - name: 运行单元测试
        run: pytest tests/unit --cov=app --cov-report=xml
      - name: 运行集成测试
        run: pytest tests/integration
      - name: 上传覆盖率报告
        uses: codecov/codecov-action@v3
  
  frontend-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: 安装依赖
        run: cd frontend && npm ci
      - name: 运行单元测试
        run: npm test -- --coverage
      - name: 运行 E2E 测试
        run: npm run test:e2e
```

### 5.2 测试门禁

| 阶段 | 必须通过的测试 | 失败策略 |
|------|---------------|---------|
| **PR 合并** | 单元测试 + 集成测试 | 阻止合并 |
| **部署 Staging** | 全部测试 | 阻止部署 |
| **部署 Production** | 全部测试 + 性能测试 | 阻止部署 |

## 七、测试最佳实践

### 7.1 命名规范

```python
# ✅ 好的测试名称
def test_create_data_source_with_valid_input_returns_201():
    """给定有效输入，创建数据源应返回 201"""
    pass

def test_clean_dialogue_with_empty_input_raises_validation_error():
    """给定空输入，清洗对话应抛出验证错误"""
    pass

# ❌ 差的测试名称
def test_1():
    pass

def test_data_source():
    pass
```

### 7.2 AAA 模式

```python
def test_evaluate_quality():
    # Arrange（准备）
    agent = QualityEvaluationAgent()
    dialogue = {"user_message": "退款", "ai_response": "请提供订单号"}
    
    # Act（执行）
    result = agent.evaluate(dialogue)
    
    # Assert（断言）
    assert result["score"] >= 0
    assert result["score"] <= 100
```

### 7.3 独立性原则

- ✅ 每个测试独立运行
- ✅ 测试间无依赖
- ✅ 测试顺序无关
- ❌ 避免共享状态

### 7.4 单一职责

```python
# ✅ 好的测试：单一职责
def test_parse_user_message():
    """仅测试用户消息解析"""
    pass

def test_parse_ai_response():
    """仅测试 AI 回复解析"""
    pass

# ❌ 差的测试：职责过多
def test_parse_dialogue_and_save_to_db_and_send_notification():
    """测试太多功能"""
    pass
```

## 十、测试维护

### 10.1 测试代码审查

**检查清单**:
- [ ] 测试名称清晰描述意图
- [ ] 遵循 AAA 模式
- [ ] 断言充分且具体
- [ ] 无硬编码数据（使用 Fixture）
- [ ] 无测试间依赖

### 10.2 定期清理

**每月审查**:
- 删除重复测试
- 更新过时测试
- 移除不再使用的 Fixture
- 优化慢速测试

### 10.3 测试债务管理

**记录测试债务**:
```python
@pytest.mark.skip(reason="TODO: 等待 API v2 实现后补充测试")
def test_new_feature():
    pass
```

**优先级**:
1. 关键路径缺失测试 → 立即补充
2. 低覆盖率模块 → 下个迭代
3. 测试性能优化 → 积压（Backlog）

## 十二、常见问题

### Q1: 如何平衡测试时间和开发时间？

**A**: 遵循测试金字塔，优先写单元测试（快速）。

| 测试类型 | 编写时间 | 维护成本 | 投入比例 |
|---------|---------|---------|---------|
| 单元测试 | 低 | 低 | 70% |
| 集成测试 | 中 | 中 | 25% |
| E2E 测试 | 高 | 高 | 5% |

---

### Q2: Prompt 测试如何保证稳定性？

**A**: 使用固定 seed + 温度 0 + Golden Test 模式。

```python
# 固定随机种子
llm = ChatAnthropic(
    model="claude-sonnet-5-5",
    temperature=0,
    seed=42
)

# Golden Test：保存基准输出
assert result == load_golden_output("test_case_1.json")
```

---

### Q3: 如何测试 Agent 的非确定性输出？

**A**: 
1. **确定性部分**：验证结构（JSON schema）、必填字段
2. **非确定性部分**：验证语义相似度（embedding 距离）
3. **人工验证**：定期抽样人工审查
