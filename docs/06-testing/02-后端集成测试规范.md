## 一、集成测试概述

### 1.1 定义
**集成测试**验证多个模块协作的正确性：
- API 路由 + 业务服务 + 数据库
- Agent + LLM + 数据库
- Celery 任务 + Redis + 数据库

### 1.2 与单元测试的区别

| 维度 | 单元测试 | 集成测试 |
|------|---------|---------|
| **范围** | 单个函数/类 | 多个模块协作 |
| **依赖** | Mock 外部依赖 | 使用真实依赖 |
| **速度** | 快（毫秒级） | 慢（秒级） |
| **数据库** | Mock | 真实测试数据库 |
| **比例** | 70% | 25% |

## 四、共享 Fixtures

### 4.1 数据库 Fixtures

```python
# tests/integration/conftest.py
import os

import pytest
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

from app.db.base import Base  # ⬜ 待实现：仓库当前无 app/db/

# 集成测试固定连 docker-compose.test.yml 的 5433 测试库
TEST_DATABASE_URL = os.getenv(
    "DATABASE_URL",
    "postgresql://aiinsight:dev_password@localhost:5433/aiinsight_test",
)


@pytest.fixture(scope="session")
def test_db_engine():
    """测试数据库引擎（会话级，所有测试共享）"""
    engine = create_engine(TEST_DATABASE_URL, pool_pre_ping=True)
    Base.metadata.create_all(bind=engine)
    yield engine
    Base.metadata.drop_all(bind=engine)
    engine.dispose()


@pytest.fixture(scope="function")
def db_session(test_db_engine):
    """数据库会话（函数级，每个测试独立，结束后回滚）"""
    Session = sessionmaker(bind=test_db_engine)
    session = Session()
    try:
        yield session
    finally:
        session.rollback()
        session.close()
```

> **不要**引用 `settings.TEST_DATABASE_URL`——`app/core/config.py` 里没有这个配置项。测试库地址通过 `DATABASE_URL` 环境变量注入，默认值即上面的 5433 连接串。

## 八、事务和并发测试

### 8.1 并发更新测试

```python
def test_concurrent_patch_keeps_single_final_state(client, auth_headers, db_session):
    """并发 PATCH 同一数据源不应产生脏数据"""
    import concurrent.futures

    from app.models.data_source import DataSource

    # Arrange
    ds = DataSource(name="测试店铺", platform="taobao")
    db_session.add(ds)
    db_session.commit()

    def patch_name(index: int) -> int:
        response = client.patch(
            f"/api/v1/datasources/{ds.id}",
            json={"name": f"并发改名-{index}"},
            headers=auth_headers,
        )
        return response.status_code

    # Act - 10 个并发请求
    with concurrent.futures.ThreadPoolExecutor(max_workers=10) as executor:
        futures = [executor.submit(patch_name, i) for i in range(10)]
        results = [f.result() for f in futures]

    # Assert - 全部成功，且最终落库的是其中一个合法值（后写覆盖先写）
    assert all(code == 200 for code in results)

    db_session.expire_all()
    final = db_session.query(DataSource).filter_by(id=ds.id).first()
    assert final.name.startswith("并发改名-")
```

> 并发用例依赖真实 PostgreSQL 的行级锁语义，**不能用 SQLite 跑**。`TestClient` 默认是同步调用，若要压真实并发需配合 `httpx.AsyncClient` + `asyncio.gather`，并用 `@pytest.mark.slow` 标记。

## 九、性能测试

### 9.1 响应时间测试

性能目标：**核心 API P95 < 2s**（与 [00-测试策略总览](./00-测试策略总览.md) 1.2 一致）。单次调用耗时波动大，因此用多次采样取分位数，而不是断言单次耗时。

```python
import time

import pytest

@pytest.mark.slow  # performance 未在 pytest.ini 注册，--strict-markers 下会报错
def test_list_datasources_p95_under_2s(client, auth_headers):
    """列表数据源 P95 响应时间应 < 2s"""
    durations = []
    for _ in range(20):
        start = time.perf_counter()
        response = client.get("/api/v1/datasources", headers=auth_headers)
        durations.append(time.perf_counter() - start)
        assert response.status_code == 200

    durations.sort()
    # 20 个样本的 P95 取第 19 个（索引 18）
    p95 = durations[18]
    assert p95 < 2.0, f"P95={p95:.3f}s 超过 2s"
```

> 若确实想用 `@pytest.mark.performance`，需先在 `backend/pytest.ini` 的 `markers` 中登记，否则 `--strict-markers` 会直接报错。

```bash
# 显示详细输出
pytest -m integration -v --tb=short

# 清理环境
docker compose -f docker-compose.test.yml down -v
```

> 集成测试与单元测试在 CI 中由**同一条命令**执行（`pytest -m "not prompt"`），本地想只跑集成层时才需要显式 `-m integration`。

### 10.2 CI 配置

集成测试**没有**单独的工作流，由 `.github/workflows/test.yml` 的 `backend` job 一并执行。CI 里用 GitHub Actions 的 `services`（端口 5432 / 6379），**不**使用 `docker-compose.test.yml`：

```yaml
# .github/workflows/test.yml（节选）
jobs:
  backend:
    name: 后端测试
    runs-on: ubuntu-latest
    services:
      postgres:
        image: pgvector/pgvector:pg14
        env:
          POSTGRES_USER: aiinsight
          POSTGRES_PASSWORD: dev_password
          POSTGRES_DB: aiinsight_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U aiinsight"
          --health-interval 5s
          --health-timeout 5s
          --health-retries 10
      redis:
        image: redis:7-alpine
        ports:
          - 6379:6379
        options: >-
          --health-cmd "redis-cli ping"
          --health-interval 5s
          --health-timeout 3s
          --health-retries 10
    defaults:
      run:
        working-directory: backend
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
          cache: pip
      - name: 安装依赖
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt -r requirements-dev.txt
      - name: 准备测试库扩展
        run: |
          PGPASSWORD=dev_password psql -h localhost -U aiinsight -d aiinsight_test -f scripts/init_db.sql
      - name: 单元测试 + 覆盖率（阈值 80%）
        env:
          DATABASE_URL: postgresql://aiinsight:dev_password@localhost:5432/aiinsight_test
          REDIS_URL: redis://localhost:6379/0
        run: pytest -m "not prompt" --cov=app --cov-report=term-missing --cov-fail-under=80
```

**本地 vs CI 的端口差异**（容易踩坑）：

| 环境 | PostgreSQL | Redis |
|------|-----------|-------|
| 本地 `docker-compose.test.yml` | 5433 | 6380 |
| CI services | 5432 | 6379 |

因此测试代码**不能写死端口**，一律从 `DATABASE_URL` / `REDIS_URL` 环境变量读取。
