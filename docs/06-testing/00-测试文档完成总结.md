## 四、测试策略

### 4.1 测试金字塔

```
          ┌─────────────────┐
          │   E2E 测试      │  5%   (慢，昂贵，全链路)
          └─────────────────┘
                 ↑
      ┌──────────────────────┐
      │    集成测试           │  25%  (中速，API+DB+Redis)
      └──────────────────────┘
                 ↑
 ┌────────────────────────────────┐
 │       单元测试                  │  70%  (快，隔离，细粒度)
 └────────────────────────────────┘
```

| **Prompt 测试** | 每个 Agent ≥ 50 用例 | 每次 Prompt 变更 |

### 9.1 AAA 模式

```python
def test_example():
    # Arrange（准备）- 设置测试数据
    agent = DataCleaningAgent()
    input_data = {"raw": "测试"}
    
    # Act（执行）- 调用被测试的函数
    result = agent.clean(input_data)

    assert result["status"] == "success"
```

## 十、常见问题

### Q1: 如何平衡测试时间和开发时间？

**A**: 遵循测试金字塔：
- 70% 单元测试（快速）
- 25% 集成测试（中速）
- 5% E2E 测试（慢速）

---

### Q2: Prompt 测试如何保证稳定性？

**A**: 
1. 使用固定 seed + 温度 0
2. Golden Test（保存基准输出）
3. 语义相似度验证（非精确匹配）

---

### Q3: 如何加速慢速测试？

**A**:
1. Mock 外部依赖（API、数据库）
2. 使用内存数据库（SQLite）
3. 并行运行（`pytest -n auto`）
4. 分离慢速测试（`@pytest.mark.slow`）
