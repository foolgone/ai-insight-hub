## 1. 产品定位

### 一句话定位

**AI Insight Hub** 是一个为 AI 客服/对话系统提供数据清洗、质量评估、知识构建和洞察分析的智能数据中台。

### 核心价值主张

```
不是审核"人工客服"
而是管理和优化"AI 客服"

通过数据中台能力
让 AI 客服持续进化
```

---

## 2. 为什么需要这个产品？

### 当前时代背景

**客服 AI 化趋势**
- 越来越多企业使用基于大语言模型的 AI 客服（自研或第三方 SaaS）
- AI 客服 24/7 在线，成本是人工的 1/10
- 但 AI 客服的质量管理成为新挑战

**AI 客服的痛点**
- ❌ AI 会"幻觉"（编造信息）
- ❌ AI 会答非所问
- ❌ AI 的知识库需要持续更新
- ❌ 缺少系统化的质量管理工具

### 传统方案的不足

**方案 1：人工抽查**
- 覆盖率低（< 5%）
- 滞后性强
- 成本高

**方案 2：规则系统**
- 规则难以穷尽
- 无法处理语义
- 维护成本高

**方案 3：单点工具**
- 功能分散
- 数据孤岛
- 缺少系统性

## 3. 产品能做什么？

### 核心功能

#### 功能 1：数据接入与清洗 🔧

**输入**：
- 第三方客服系统导出的数据（Excel/CSV/JSON/数据库）
- 可能是非结构化的聊天记录
- 数据格式不统一、质量参差不齐

**处理**：
- AI 智能解析（非结构化 → 结构化）
- 去重（完全重复 + 相似度去重）
- 数据标准化（统一 JSON 格式）
- 质量评估（完整性、有效性打分）

**输出**：
- 干净、标准化的对话数据
- 数据质量报告
- 可直接用于分析的 JSON

---

#### 功能 2：AI 质量评估 🤖

**评估维度（统一为 5 维）**：

```
1. 准确性 accuracy
   - 回答是否正确
   - 是否有事实错误
   - 是否符合知识库

2. 完整性 completeness
   - 是否充分回答
   - 是否遗漏关键信息
   - 是否需要追问

3. 语气与体验 tone
   - 语气是否礼貌
   - 是否有同理心
   - 表达是否清晰

4. 合规性 compliance
   - 是否有违规内容
   - 是否泄露敏感信息
   - 是否符合平台规则

5. 幻觉 hallucination
   - 是否编造知识库中不存在的信息
   - 是否捏造事实、数字、承诺
   - 是否越界承诺（价格/时效/售后）
```

> 口径说明：5 个维度的机器可读 key 固定为 `accuracy` / `completeness` / `tone` / `compliance` / `hallucination`，各维度与总分均为 **0–100**。早期版本把「幻觉」并入「合规性」、把「语气」写作「用户体验」，现已统一为 5 维。

**输出**：
- 每条对话的质量评分（0-100）
- 问题标注（准确/幻觉/不完整等）
- 改进建议
- 风险预警

---

#### 功能 3：知识库智能构建 📚

**能力**：

```
1. 自动提取 FAQ
   - 识别高频问题
   - 提取标准答案
   - 聚类相似问题

2. 发现知识盲区
   - 未覆盖的问题
   - 答案不完整的问题
   - 优先级排序

3. 知识组织
   - 问题分类（产品/售后/咨询）
   - 构建问题树
   - 生成知识图谱

4. 智能推荐
   - 推荐待补充的内容
   - 推荐优化方向
```

**输出**：
- FAQ 列表（JSON/Markdown）
- 知识盲区报告
- 知识图谱
- 优化建议

---

#### 功能 4：客户洞察分析 📊

**分析维度**：

```
1. 诉求分类
   - 咨询类、投诉类、建议类
   - 自动分类统计

2. 情感分析
   - 满意、中性、不满、愤怒
   - 情感趋势变化

3. 趋势分析
   - 高频问题排行
   - 新出现的问题
   - 季节性规律

4. 痛点挖掘
   - 未解决的问题
   - 反复出现的问题
   - 转人工的场景
```

**输出**：
- 客户诉求报告
- 情感趋势图
- 痛点清单
- 产品改进建议

---

#### 功能 5：数据报告生成 📄

**报告类型**：

```
1. AI 表现报告
   - 整体质量评分
   - 各维度得分
   - 问题分布
   - 改进建议

2. 知识库健康报告
   - 覆盖率分析
   - 知识盲区
   - 更新建议

3. 客户洞察报告
   - 诉求趋势
   - 满意度变化
   - 痛点分析

4. 运营数据报告
   - 对话量统计
   - 问题解决率
   - 转人工率
```

**输出格式**：
- PDF（专业报告）
- Excel（数据导出）
- Markdown（在线查看）
- PPT（汇报演示）

> 待确认：需求讨论记录中只提出 PDF / Excel / Markdown 三种导出格式，**未提 PPT**。PPT 是否纳入 MVP 需业务方确认；若纳入，MVP 的实现方式（模板渲染 vs 第三方库）也待定。

## 7. 核心指标

### 产品指标

```
1. 数据处理
   - 清洗准确率：> 95%
   - 处理速度：1000 条/分钟（待实测确认）
   - 去重准确率：> 90%

2. AI 评估
   - 评估准确率：> 85%
   - 幻觉检测率：> 90%
     · 定义（待确认，建议口径）：在人工标注为「含幻觉」的对话子集上，被系统判为幻觉的比例
       = 命中数 / 人工标注幻觉样本总数（即召回率 recall）
     · 验收标准：在冻结的标注基线集（规模待确认，建议 ≥ 200 条）上 recall > 90%，
       同时误报率（被判为幻觉但人工判定无幻觉的比例）< 10%
   - 评估速度：单条评估 ≤ 2 秒（P95）

3. 知识提取
   - FAQ 提取准确率：> 80%
   - 知识盲区覆盖率：> 85%
     · 定义（待确认，建议口径）：系统识别出的知识盲区条目数 / 人工确认的知识盲区条目总数
     · 验收标准：在人工确认的盲区清单（规模待确认，建议 ≥ 100 条）上覆盖率 > 85%，
       且被判出的盲区经人工复核通过率 > 80%

4. 系统性能
   - API 响应时间：P95 < 2 秒（同步接口；异步任务另计，不计入此口径）
   - 系统可用性：> 99.5%
```

> 说明：两个带「定义」的指标早期只有名字、没有分子分母，无法验收，现补充口径；**分母规模**（标注基线集大小）与阈值需业务方最终确认，确认后应回写到本文档并冻结。

## 8. 技术优势

### AI 原生

- 基于 LangChain/LangGraph 构建
- LLM 统一接入 **DeepSeek V4.1 Flash**（`langchain-deepseek` 官方集成）；模型 id 由 `.env` 的 `DEFAULT_LLM_MODEL` 配置（默认 `deepseek-flash`），不写死在代码里
- Agent 化架构，灵活扩展

### 数据中台

- 统一数据模型
- 多源数据接入
- 标准化处理流程

### 开箱即用

- 无需配置
- 自动化流程
- 可视化界面
