## 💡 核心需求总结

### 需求 1：数据清洗与标准化 ⭐⭐⭐

**开发者强调：**
> "数据清洗，针对第三方数据做json"

**需求描述：**
```
输入：
- 第三方客服系统导出的数据
- 可能是非结构化的（文本、Excel、CSV）
- 数据质量参差不齐

处理：
- AI 智能解析
- 去重（完全重复 + 相似对话）
- 标准化字段
- 转换为统一 JSON 格式

输出：
- 干净的、标准化的 JSON 数据
- 可直接用于分析
- 质量评估报告
```

**重要性：P0（必须有）**

---

### 需求 2：AI 客服质量评估 ⭐⭐⭐

**开发者强调：**
> "审核AI客服的对话，判断AI客服的回答是否正确/合适"

**需求描述：**
```
评估维度：
1. 准确性
   - 回答是否正确
   - 是否有事实错误
   - 是否符合知识库

2. 合适性
   - 语气是否合适
   - 是否有礼貌
   - 是否有同理心

3. 完整性
   - 是否充分回答
   - 是否遗漏信息

4. 合规性
   - 是否有幻觉（编造）
   - 是否有违规内容
   - 是否泄露敏感信息

输出：
- 质量评分（0-100）
- 问题标注
- 改进建议
- 风险预警
```

**重要性：P0（必须有）**

---

### 需求 3：知识库智能构建 ⭐⭐⭐

**开发者强调：**
> "构建知识库，你要了解知识库应该收录哪些内容"

**需求描述：**
```
能力 1：自动识别应该收录什么
- AI 分析对话
- 识别高频问题
- 提取标准答案
- 评估内容质量

能力 2：知识组织
- 问题分类
- 相似问题聚类
- 构建问题树
- 生成 FAQ

能力 3：发现知识盲区
- 识别未覆盖的问题
- 识别答案不完整的问题
- 优先级排序

能力 4：持续更新
- 新问题自动识别
- 知识过时检测
- 更新建议
```

**重要性：P0（必须有）**

---

### 需求 4：客户诉求收集 ⭐⭐⭐

**开发者强调：**
> "收集客户诉求"

**需求描述：**
```
能力 1：诉求识别

能力 3：痛点挖掘

能力 4：趋势分析
- 诉求变化趋势

输出：
- 客户诉求分布
- 高频问题列表

- 产品改进建议
```

## 🏗️ 技术架构需求

### 后端框架需求

**开发者原话：**
> "架构我想后端用python的langchain/langgraph，等等"

**技术选型：**
```
核心框架：
- Python
- LangChain（AI Agent 框架）
- LangGraph（工作流编排）

原因：
- Python 是 AI 生态的首选
- LangChain 提供强大的 Agent 能力
- LangGraph 适合复杂工作流
```

**架构模式：**
```
AI Agent 化架构：
- 数据清洗 Agent
- 质量评估 Agent
- 知识提取 Agent
- 洞察分析 Agent
- 报告生成 Agent
```

---

### 数据隔离需求

**开发者原话：**
> "比如D:\code\xiaoduo\github-project\chat-resume，这个项目，一个每一个简历可以进行修改和AI进行回答"

**参考项目：chat-resume**
```
特点：
- 每一份简历独立
- 可以单独修改
- AI 针对单份简历回答
```

**借鉴到新项目：**
```
概念：数据源（DataSource）

每一个数据源：
- 独立管理
- 独立分析
- 独立报告
- 数据隔离

示例：
- 数据源 1：2026年1月客服对话
- 数据源 2：2026年2月客服对话
- 数据源 3：电商平台对话
- 数据源 4：APP 内对话

每个数据源：
- 可以独立导入
- 可以独立分析
- 可以独立配置
- 互不干扰
```

**数据模型：**
```sql
data_sources (数据源表)
├── id
├── name
├── type
└── config

每个数据源下：
├── raw_data (原始数据)
├── cleaned_data (清洗后数据)
├── analysis_results (分析结果)
└── knowledge_base (知识库)
```

---

### 定制化操作需求

**开发者原话：**
> "那么我想要的是每一份数据源，可进行定制化操作，交由AI"

**需求理解：**
```
每个数据源可以：
1. 自定义配置
   - 自定义标签
   - 自定义评分标准
   - 自定义分析规则

2. 独立的 AI 处理
   - 数据清洗（AI）
   - 质量评估（AI）
   - 知识提取（AI）
   - 报告生成（AI）

3. 灵活的工作流
   - 可以只做数据清洗
   - 可以只做质量评估
   - 可以完整流程
   - 可以自定义流程
```

**工作流示例：**
```
数据源 A（客服对话）：
1. 数据导入
2. 数据清洗 (AI)
3. 质量评估 (AI)
4. 知识提取 (AI)
5. 报告导出

数据源 B（销售话术）：
1. 数据导入
2. 数据清洗 (AI)
3. 质量评估 (AI)
4. 报告导出
（跳过知识提取）

数据源 C（内容审核）：
1. 数据导入
2. 数据清洗 (AI)
3. 风险评估 (AI)
4. 报告导出
（不同的评估标准）
```

## 📊 完整的工作流程

### 开发者期望的完整流程

**开发者原话：**
> "比如1、数据导入，2、数据分析，3、数据清洗，4、数据结构化，5、报告导出，6、知识库构建指导 7、质量评估"

**标准工作流：**

```
Step 1：数据导入
- 上传文件（JSON/CSV/Excel/TXT）
- 或 API 对接
- 或数据库导入

Step 2：数据清洗
- AI 解析非结构化数据
- 去重（完全 + 相似度）
- 标准化字段
- 质量评估

Step 3：数据结构化
- 转换为标准 JSON
- 统一数据模型
- 补全缺失字段

Step 4：数据分析
- 质量评估（AI）
- 客户洞察（AI）
- 趋势分析

Step 5：知识库构建
- 提取 FAQ（AI）
- 发现知识盲区（AI）
- 构建知识图谱

Step 6：质量评估
- AI 客服表现评分
- 问题标注
- 改进建议

Step 7：报告导出
- 生成报告（AI）
- 多格式导出
- 可视化展示
```

**流程特点：**
- AI 驱动（每一步都有 AI 参与）
- 自动化（最少人工干预）
- 灵活（可跳过某些步骤）
- 可定制（每个数据源独立配置）
