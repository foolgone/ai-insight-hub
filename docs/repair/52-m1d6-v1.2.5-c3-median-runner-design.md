## 1. 目标

在 v1.2.5 单案例诊断中同时执行 C：

- Q23 F 跑 **3 次**，报 median / min / max，以及每次 claim 分解；
- Q23 C / R 各 1 次；
- Q21 / Q11 各 1 次 × 3 指标；
- 3 次中允许记录 invalid 后继续收集，但只限 `diagnostic_only`；
- **不写 PASS、不计入 10 条、不替代正式验收**。

C 的目的不是“跑到通过”，而是测量 Q23 在窄带 `[0.4, 0.5]` 下的分布与 claim 分解稳定性。

## 2. 调用矩阵与预算

### 2.1 调用矩阵

| 段 | primary | patch |

## 3. 执行流程

### 3.1 总体顺序

```text
preflight（SHA/冻结/ledger 空/自测）
  ↓
Q23 F run 1 → 记录 F / F_strict / patch / claims
  ↓
Q23 F run 2 → 记录 F / F_strict / patch / claims
  ↓
Q23 F run 3 → 记录 F / F_strict / patch / claims
  ↓
Q23 C / R（1 次）
  ↓
Q21（1 次 × 3 指标）
  ↓
Q11（1 次 × 3 指标）
  ↓
汇总 median / min / max / invalid / target hit
  ↓
写 results JSON + analysis + report + ledger SHA
```

### 3.2 Q23 F × 3

- 每次都是独立的 `judge_trace(session=None, trace=q23_trace, metrics=["faithfulness"], prompt_version="v1.2.5", agent_factory=fresh_factory)`；
- 每次都创建新的 `RagJudgeAgent` 与新的 `InstrumentedLLM`，不得复用上一次的 agent/LLM；
- 每次记录：
  - `run_id`（`Q23-F#1` / `#2` / `#3`）；
  - F / F_strict status、score、counts；
  - patch 是否触发、patch applied claims、refusal、merged 是否生成；
  - 初始 claims 的 claim_id / type / subtype / support_status / quotes；
  - F 是否在 `[0.4, 0.5]`。
- 某一次 invalid 不停止后续 run；记录 `invalid_runs` 后继续。
- 每次 patch 最多 1 次；patch 失败不 retry。

### 3.3 Q23 C / R

- 1 次 `judge_trace(..., metrics=["answer_correctness", "answer_relevancy"])`；
- 记录 C / R status、score、target pass；
- C 的 `correctness_first_sentence_warning` 必须记录；
- 不重复 3 次（C 诊断只要求 F × 3）。

### 3.4 Q21 / Q11

- 各 1 次 × 3 指标；
- 记录 target pass、quote 连续性、claim 级明细；
- Q21 的 exemption claim / 运费/换货 quote 检查保持 v1.2.4 规则；
- Q11 的 quote 连续性与三项目标保持 v1.2.4 规则；
- 若 invalid，记录后继续下一 case；不写 PASS。

## 4. Diagnostic 继续/停止规则

### 4.1 继续（只记录，不硬停止）

- 任一 F/C/R `invalid(contract_violation)`；
- patch refusal / patch schema invalid；
- Q23 某次 F target miss；
- Q21 / Q11 单次 target miss；
- 某次 F `failed(execution)`（非凭证原因）——记录后继续，除非预算/ledger/指纹问题。

### 4.2 硬停止

- `started > 18` 或 `cost > CNY 0.40`；
- LLM 凭证未配置/失效；
- Prompt / MANIFEST / fixture / target / patch schema / example / validator SHA 漂移；
- ledger 缺失、SHA 不匹配、`uncertain_call=true`；
- 预检失败；
- 进程中断/无法继续。

硬停止时保留已收集结果，写 `stop_reason`；不得补跑“直到通过”。

## 5. Median / Min / Max 定义

```text
valid_scores = [score for run in Q23 F runs
                if run.status == "evaluated" and score is not None]
invalid_runs = [run_id for run in Q23 F runs if run not in valid]
median = statistics.median(valid_scores) if len(valid_scores) >= 2 else None
min = min(valid_scores) if valid_scores else None
max = max(valid_scores) if valid_scores else None
target_hit_count = count(0.4 <= score <= 0.5 for score in valid_scores)
median_in_target = 0.4 <= median <= 0.5 if median is not None else None
```

规则：

- **不得**把 invalid 当 0 分填入 median；
- `valid_scores` 少于 2 时，`median=null`，标 `insufficient_valid_runs=true`；
- 报告同时给 `invalid_runs`、`target_hit_count`、`target_hit_rate`；
- 不要求 3 次全部在区间；不把 median 在区间写成 PASS。

## 10. 决策（2026-11-23，审核通过）

1. Q23 F 3 次使用完全相同的 trace/item；只改变 run_id，不改变输入。
2. 3 次共享 patch 预算：每次最多 1 patch，总计最多 3 patch；不跨 run 复用。
3. Q23 C/R 在 3 次 F 之后跑；避免 C/R 调用影响 F 的上下文/预算顺序。

5. 报告可以写 `median_in_target=true`，但不得写 PASS/verified。
6. **P1-5**：Q23 C/R 各 1 次只是 diagnostic snapshot，不得宣称稳定；正式 10 条闸门仍按 HG 目标边界重复 3 次。
7. 预算 18 calls / CNY 0.40 按 11 primary + 5 patch + 2 shared reserve 复算；若实现后实际单价变化，申请时重新估算，但不得复用 v1.2.4 的 14/0.30。
