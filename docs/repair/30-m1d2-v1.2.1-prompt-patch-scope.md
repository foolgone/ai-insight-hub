## 1. 结论

1. Q11 的 invalid 是**证据违约**，不是 Service bug，也不是“逐字校验过严”。
2. Q11 的 C1 是连续文档；Judge 把两段不相邻的句子拼成一条 `quote`，中间跳过了“审核通过后……”一句。
3. 按 r2 / `12` §5.2 / `15` §3.3，`quote` 必须是 context 的逐字连续子串；拼接两个非连续片段必须 `invalid(contract_violation)`。
4. 不放宽 Service、不豁免 Q11、不修改 fixture 来让 quote 变连续。
5. 下一步只开 **v1.2.1 Prompt patch**，只改 evidence 连续性规则；冻结后重新提交 10 条申请。

## 2. Q11 复核证据

fixture：`docs/repair/phase3e/pilot-10-v1.1.5-gate.json`，SHA `dc7be14b…`。

C1 原文（节选）：

```text
订单签收后 7 天内可申请无理由退款。
审核通过后，款项将在 1-3 个工作日内原路退回。
定制类商品、生鲜食品、已激活的虚拟商品不支持无理由退款。
```

Judge 输出：

```json
{
  "claim": "签收第 5 天的定制商品不可以无理由退款",
  "claim_type": "factual_claim",
  "claim_subtype": "condition",
  "support_status": "supported",
  "evidence_refs": [
    {
      "context_id": "C1",
      "quote": "订单签收后 7 天内可申请无理由退款。定制类商品、生鲜食品、已激活的虚拟商品不支持无理由退款。"
    }
  ]
}
```

该 quote 跳过了中间的“审核通过后……”一句，不是 C1 的连续子串。Service 返回：

```json
[{"claim_id": "cl1", "code": "quote_not_found",
  "message": "evidence_ref violates v3 contract", "context_id": "C1"}]
```

判定：

| 项 | 结论 |
|---|---|
| 是否 Service bug | 否 |
| 是否 fixture 格式问题 | 否；C1 是正常连续文档 |
| 是否逐字校验过严 | 否；r2 明确禁止拼接非连续片段 |
| 正确判定 | `invalid(contract_violation)`，strict 同步 invalid |
| 是否可放宽 | 否；放宽会让“跳过中间反例/条件”的 quote 通过 |

补充：Q11 的 claim 本可以用第二句单独支持：

```text
定制类商品、生鲜食品、已激活的虚拟商品不支持无理由退款。
```

因此规则是可达的，不需要拼接第一句。

## 4. Prompt 规则草案（只写设计，不落文件）

在 v1.2.1 Faithfulness Prompt 的 evidence 规则中增加/强化：

1. **一条 `evidence_ref` 只能是一个连续子串**；`quote` 必须从 context 逐字连续复制。
2. **不得把两段不相邻的原文拼成一条 quote**；中间跳过任何字符/句子都不允许。
3. 如果 claim 需要两个片段支持：
   - 拆成两条 claim，各自引一个连续片段；或
   - 只选能独立支持该 claim 的最短连续片段。
4. 不得用省略号、省略中间句、跨段拼接、改写标点、补主语/谓词来“制造”连续 quote。
5. `conflict` 仍需两条独立 `evidence_refs`；每条各自连续，不能把两处原文拼成一条。
6. 找不到单条连续子串能支持时，按事实类型判 `insufficient_evidence`；不得用拼接 quote 维持 `supported`。

建议反例（写入 Prompt 的模式级示例）：

```text
Context C1:
A。B。C。

Bad quote: "A。C。"        # 跳过 B，不是连续子串 -> invalid
Good: claim A -> quote "A。"；claim C -> quote "C。"
     或只保留能独立支持该 claim 的那一条。
```

## 5. Q11 回归 fixture（设计）

新增一个**Service 契约回归**，不调用真实模型：

| 项 | 内容 |
|---|---|
| fixture | Q11 固定 query/answer/contexts/gold |
| bad output | 使用 Q11 的拼接 quote，`support_status=supported` |
| expected | `faithfulness=invalid`、`invalid_reason=contract_violation`、error code `quote_not_found`；strict 同步 invalid |
| good output | 只引“定制类商品、生鲜食品、已激活的虚拟商品不支持无理由退款。” |
| expected good | F evaluated，claim 级 supported，不因缺少第一句被误判 |

建议测试名：

- `test_q11_noncontiguous_quote_invalid`
- `test_q11_contiguous_quote_supported`

这两个测试锁定 Service 契约，防止未来“放宽逐字校验”回归；不改 Service 行为。
