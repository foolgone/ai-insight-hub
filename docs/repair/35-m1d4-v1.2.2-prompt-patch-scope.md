## 1. 结论

1. Q23 invalid 判定正确，停止正确；不是 Service bug，也不是逐字校验问题。
2. Q23 的问题是 Judge 输出/修复轮没有遵守既有 absence 规则：
   - `claim_type=factual_claim` + `claim_subtype=absence`；
   - `supported` 但 `evidence_refs=[]`；

3. Q21 是 target miss，不是 invalid；F=1.0 来自“证据只沾边但被判 supported”的语义错误。
4. Q21 不能靠改目标变成 PASS；先修证据语义，再人工复核目标 0.6–0.7 是否仍成立。
5. v1.2.2 只加两类通用规则，不加案例特例；不改 Service invalid 契约。

## 2. Q23 复核

原始输出关键问题：

```json
{
  "claim": "该时限是硬性要求，文档未提及例外情形或宽限期。",
  "claim_type": "factual_claim",
  "claim_subtype": "absence",
  "support_status": "supported",
  "evidence_refs": [
    {"context_id": "C1", "quote": "生鲜食品质量问题需在签收后 24 小时内拍照反馈。"}
  ]
}
```

问题：

| # | 问题 | 正确口径 |
|---|---|---|
| 1 | `absence` 是 non_factual，不能配 factual_claim | `non_factual` + `absence` |
| 2 | `supported` 不能没有有效 evidence_refs | `support_status=null`、`evidence_refs=[]` |
| 3 | 混合句未拆分 | 事实部分 factual；absence 部分 non_factual |
| 4 | 修复轮仍未合法 | `StructuredOutputError` → invalid，停止正确 |

Q23 不是 Q11 的逐字连续问题；这次是 subtype/claim_type 与 supported evidence 的契约问题。

## 3. Q21 复核

Q21 F=1.0，目标 0.6–0.7，属于 **target FAIL**，但因 Q23 先触发 invalid，按规则停止，未继续。

关键 claim：

```json
{
  "claim": "若商品存在质量问题，则不受 7 天无理由限制，仍可依据保修或退换货政策主张权益。",
  "claim_type": "factual_claim",
  "claim_subtype": "condition",
  "support_status": "supported",
  "evidence_refs": [
    {
      "context_id": "C1",
      "quote": "因质量问题产生的退换货运费由商家承担；非质量问题的退货运费由买家承担。"
    }
  ]
}
```

该 quote 是逐字连续子串，Service 不会拦；但它只支持“运费承担”，不支持“质量问题不受 7 天限制”。这是 **semantic support 错误**，不是结构违约。

另一处：

```json
{
  "claim": "该限制适用于“普通商品”……",
  "claim_type": "factual_claim",
  "claim_subtype": "condition",
  "support_status": "supported",
  "evidence_refs": [
    {"context_id": "C1", "quote": "定制类商品、生鲜食品、已激活的虚拟商品不支持无理由退款。"}
  ]
}
```

该 quote 只列排除项，不能直接支持“普通商品适用”的反推；应 insufficient，除非文档明确写出。

Q21 的 F=1.0 是“过度支持”，不是质量更好；不能通过改目标解决。

## 5. v1.2.2 规则范围

### 5.1 absence / mixed sentence

1. “文档未提及/未说明/未规定……” → `non_factual` / `absence`；
2. absence 的 `support_status=null`、`evidence_refs=[]`；
3. 混合句必须拆分：
   - 事实部分 → factual claim；
   - absence/文档覆盖部分 → non_factual；
4. 禁止 `factual_claim` + `absence` + `supported`；
5. 禁止给 absence 附 evidence 来“证明未提及”。

### 5.2 evidence 必须直接支持 claim

1. quote 不仅要逐字连续，还必须支持 claim 的谓词/条件/结论；
2. 不得用“运费承担”支持“质量问题不受 7 天限制”这类仅主题相关的 quote；
3. `derived` claim 必须引用推导所依据的前提规则，不能引用邻近但无关的规则；
4. 找不到直接支持时判 `insufficient_evidence`，不要用相关 quote 硬撑 supported；
5. `condition` / `policy_scope` / `policy_relationship` 同样要求直接依据，不得只凭主题词。

### 5.3 repair example

建议在 v1.2.2 Agent 的 v3 repair example 中增加一个合法示例：

```json
{
  "claim_id": "cl1",
  "claim": "文档未提及超时后的申诉渠道。",
  "claim_type": "non_factual",
  "claim_subtype": "absence",
  "support_status": null,
  "is_contradictory": false,
  "contradiction_with": [],
  "evidence_refs": [],
  "reason": "absence 不需要证据"
}
```

并在现有 factual 示例旁说明：

```text
如果错误是 factual_claim + absence + supported：
- 改成 non_factual + absence + support_status=null + evidence_refs=[]；或
- 拆成 factual 事实句 + non_factual absence 句。
```

repair example 只改 Agent 的示例，不改 Service 校验。
