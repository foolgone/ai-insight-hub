## 1. 结论

1. 新增 evidence-only patch schema：只含 `fixes[claim_id, evidence_refs]`；`extra="forbid"`，不暴露任何语义字段。
2. v1.2.4 + faithfulness 使用独立 patch 流程：初始 Schema 单次解析；quote 错误触发 1 次 patch；不做 full-output repair。
3. patch 支持完整 replacement set：单 quote、多 ref、conflict 2 条 quote 均可；conflict 只有 1 条或 nested 会 invalid。
4. effective claim_id：`claim_id or cl{index}`；null claim_id 可 patch，合并后仍保持 null。
5. 合并只替换目标 claim 的 `evidence_refs`；其它字段逐字保留。
6. patch Schema 失败、quote 非连续、未知/重复 claim_id、额外语义字段均 invalid；`agent_contract.final_errors` 记录真实 `validation_errors`。
7. C prompt 增加首句/结论矛盾硬上限；v1.2.4 C warning 记录 `correctness_first_sentence_warning`，不新增 C repair。
8. F Prompt 保持 v1.2.3 SHA；C 变化；R 保持；泄漏审计 0。
9. 全量 `pytest -m "not prompt"` 1101 条通过；black/flake8/mypy/lint-imports 通过；静态校验 23/23 pass。

## 3. 实现内容

### 3.1 Patch Schema

新增 `backend/app/schemas/agents/rag_judge_patch.py`：

```python
class EvidenceFix(BaseModel):
    model_config = ConfigDict(extra="forbid")
    claim_id: str
    evidence_refs: list[EvidenceRef]  # min 1, max 20

class EvidencePatch(BaseModel):
    model_config = ConfigDict(extra="forbid")
    fixes: list[EvidenceFix]
```

无 claim 文本/type/subtype/support_status/is_contradictory/contradiction_with。

### 3.2 Agent patch 流程

- `BaseAgent` 增加可覆盖 `_parse_structured_output` hook；默认行为不变。
- `RagJudgeAgent` 仅 v1.2.4 + faithfulness 覆盖：
  - 初始完整输出单次 Schema 解析（方案 B，`max_attempts=1` 等价）；
  - 初始 Schema 失败 → 直接 `StructuredOutputError`，无 full-output repair；
  - quote 预校验失败 → 1 次 patch 模型调用；
  - patch Schema 解析 → claim 白名单 → shared validator → conflict 检查 → merge；
  - 合并后重新完整校验；Service 仍是最终权威。
- 仅 v1.2.4 的 patch example 使用 `_patch_example`；v1.2.3 及更早修复路径不变。

### 3.3 合并与 effective claim_id

- `effective_claim_id = claim.claim_id or f"cl{index}"`；
- patch 请求/白名单/merge 使用 effective ID；
- 合并只替换目标 claim `evidence_refs`；
- 原 claim_id 保持 `null`，不被写回 effective ID；
- 其它字段逐字保留。

### 3.4 final_errors

- initial Schema / patch Schema / patch validation 失败时，写入
  `agent_contract.final_errors`；
- `StructuredOutputError.validation_errors` 被保留；
- Service invalid F 与 F_strict 均携带 `agent_contract`；
- 测试覆盖 patch 字段写成字符串、额外 `support_status`、非连续 quote、初始 Schema 失败。

### 3.5 C 首句规则

- v1.2.4 `answer_correctness.txt` 增加“首句/结论矛盾硬上限”；
- `wrong_facts` 命中首句/最终结论 → 固定 0.0–0.2；
- C warning：score>0.2 时记录 `correctness_first_sentence_warning`，不覆盖分数；
- target 仍 `[0.0, 0.2]`；
- 新 Prompt 无 gate case 原文；v1.2.4 泄漏审计 0。

### 3.6 Ledger

设计已定义；本轮未启动任何 Judge 诊断 runner，ledger 将在下一次单案例申请的执行 driver 中落地（append-only、started 计数、uncertain_call）。本轮不伪造 ledger 数据。
