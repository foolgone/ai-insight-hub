## 2. 技术栈选择

### 前端

```
核心框架：
- React 18        # UI 框架
- Vite 5          # 构建工具
- TypeScript      # 类型安全（可选）

UI 组件：
- TailwindCSS 3   # 样式
- Recharts        # 图表
- React Query     # 数据获取
- Zustand         # 状态管理（可选）

工具库：
- Axios           # HTTP 客户端
- date-fns        # 日期处理
- lodash          # 工具函数
```

### 后端

```
核心框架：
- Python 3.11+    # 编程语言
- FastAPI         # Web 框架
- Uvicorn         # ASGI 服务器

AI 框架：
- LangChain       # AI 应用框架
- LangGraph       # 工作流编排
- langchain-deepseek  # LLM 接入（DeepSeek V4.1 Flash，模型 id 由 .env 的 DEFAULT_LLM_MODEL 决定）

ORM & 迁移：
- SQLAlchemy 2.0  # ORM
- Alembic         # 数据库迁移

数据处理：
- Pandas          # 数据分析
- NumPy           # 数值计算
- sentence-transformers  # 文本向量（paraphrase-multilingual-MiniLM-L12-v2，384 维）
```

### 数据库

```
主数据库：
- PostgreSQL 14+  # 关系型数据库 + 向量搜索 (pgvector)
  ├─ pgcrypto    # UUID 生成（gen_random_uuid()，PG13+ 内置）
  ├─ pgvector    # 向量搜索扩展（VECTOR(384)，HNSW 索引）
  ├─ pg_trgm     # 中文/模糊检索（MVP 使用）
  └─ zhparser    # 中文分词（⚠️ 仅自建镜像才可用，默认镜像不含，MVP 不启用）

缓存：
- Redis 7+        # 缓存 & 消息队列

文件存储：
- MinIO           # 对象存储（S3 兼容）
# 或 AWS S3      # 云存储（可选）
```

### 部署

```
容器化：
- Docker          # 容器
- Docker Compose  # 本地开发

CI/CD：
- GitHub Actions  # 自动化

监控：
- Prometheus      # 指标收集
- Grafana         # 可视化
```

## 3. 数据模型设计

> **表结构以 [`03-数据库设计.md`](./03-数据库设计.md) 为唯一事实源。**
> 本文档不再内嵌建表 SQL，避免字段名、量纲、枚举在两处漂移。
> 修改表结构时只改 `03-数据库设计.md`，本文档只维护「表清单索引」。

### 3.1 表清单索引

| # | 表名 | 用途 | 关键口径 |
|---|---|---|---|
| 1 | `users` | 用户与配额 | `role IN ('admin','user','viewer')` |
| 2 | `data_sources` | 数据源与配置 | `config.evaluation_dimensions` 默认 5 维 |
| 3 | `raw_data` | 原始数据（MVP 普通表，不分区） | `raw_content JSONB` |
| 4 | `cleaned_data` | 清洗后对话 | `user_message` / `ai_response` TEXT，`quality_score` 0–100 |
| 5 | `analysis_results` | 质量/知识/洞察分析结果 | `analysis_type IN ('quality','knowledge','insight','other')` |
| 6 | `knowledge_base` | FAQ 与向量 | `source_dialogue_ids UUID[]`，`embedding VECTOR(384)` |
| 7 | `reports` | 报告与导出文件 | `format IN ('pdf','excel','markdown','html')` |
| 8 | `tasks` | 异步任务队列 | `progress` 0–100 |
| 9 | `api_keys` | API Key 与作用域 | `scopes TEXT[]` |
| 10 | `audit_logs` | 审计日志（MVP 普通表，不分区） | `id BIGSERIAL` |
| 11 | `webhooks` | Webhook 配置（Phase 2 使用） | `events TEXT[]` |

### 3.2 与本文档相关的统一口径

- **向量**：`VECTOR(384)`，嵌入模型 `paraphrase-multilingual-MiniLM-L12-v2`，索引类型 **HNSW**（`m = 16`、`ef_construction = 64`）。
- **质量分**：0–100（不是 0–1）。
- **评估维度**：`accuracy / completeness / tone / compliance / hallucination` 共 5 维。
- **中文检索**：MVP 用 `pg_trgm` + `ILIKE` 降级；zhparser 需自建镜像，默认镜像不支持。
- **分区**：MVP 不分区，普通表 + 索引；分区方案见 [`04-development/11-数据库分区策略调整.md`](../04-development/11-数据库分区策略调整.md)。

## 4. API 设计

### RESTful API 规范

#### 基础路径

```
Base URL: http://localhost:8000/api/v1
```

#### 数据源管理

```http
# 创建数据源
POST /datasources
Body: {
  "name": "客服对话-2026年1月",
  "type": "customer_service",
  "description": "...",
  "config": {}
}

# 获取数据源列表
GET /datasources?page=1&limit=20

# 获取单个数据源
GET /datasources/{id}

# 更新数据源
PATCH /datasources/{id}

# 删除数据源
DELETE /datasources/{id}
```

#### 数据导入

```http
# 上传文件
POST /datasources/{id}/upload
Content-Type: multipart/form-data
Body: file

# 获取导入/清洗任务状态
GET /tasks/{task_id}

# 触发数据清洗
POST /datasources/{id}/clean
```

#### 分析

```http
# 质量评估
POST /datasources/{id}/analyze/quality
Body: {
  "data_ids": [...],  // 可选，不传则全部
  "options": {}
}

# 获取评估结果
GET /datasources/{id}/analysis/quality?page=1

# 知识提取
POST /datasources/{id}/extract-knowledge

# 客户洞察
POST /datasources/{id}/analyze/insights
```

#### 知识库

```http
# 获取 FAQ
GET /datasources/{id}/knowledge/faq?category=产品

# 搜索知识库
GET /datasources/{id}/knowledge/search?q=退款

# 获取知识盲区
GET /datasources/{id}/knowledge/gaps
```

#### 报告

```http
# 生成报告
POST /datasources/{id}/reports
Body: {
  "type": "quality",  // quality / knowledge / insight / comprehensive
  "format": "pdf"     // pdf / excel / markdown / html
}

# 获取报告列表
GET /datasources/{id}/reports

# 下载报告
GET /reports/{report_id}/download
```

## 5. AI Agent 设计

### Agent 架构

#### 1. 数据清洗 Agent

```python
class DataCleaningAgent:
    """
    功能：
    - 解析非结构化数据
    - 去重（完全 + 相似度）
    - 标准化字段
    - 填充缺失值
    
    输入：raw_data
    输出：cleaned_data + quality_score
    """
    
    tools = [
        "parse_unstructured",  # 解析工具
        "deduplicate",         # 去重工具
        "normalize",           # 标准化工具
        "fill_missing"         # 填充工具
    ]
```

#### 2. 质量评估 Agent

```python
class QualityAssessmentAgent:
    """
    功能：
    - 评估准确性
    - 评估完整性
    - 检测幻觉
    - 评估礼貌度
    
    输入：conversation + knowledge_base
    输出：quality_scores + issues + suggestions
    """
    
    dimensions = [
        "accuracy",      # 准确性
        "completeness",  # 完整性
        "hallucination", # 幻觉检测
        "tone",          # 语气
        "compliance"     # 合规性
    ]
```

#### 3. 知识提取 Agent

```python
class KnowledgeExtractionAgent:
    """
    功能：
    - 提取高频问题
    - 提取标准答案
    - 聚类相似问题
    - 发现知识盲区
    
    输入：conversations
    输出：faq_list + knowledge_gaps
    """
    
    steps = [
        "extract_questions",   # 提取问题
        "extract_answers",     # 提取答案
        "cluster_similar",     # 聚类
        "find_gaps"            # 发现盲区
    ]
```

#### 4. 报告生成 Agent

```python
class ReportGenerationAgent:
    """
    功能：
    - 收集数据
    - AI 分析
    - 生成 Markdown
    - 导出多格式
    
    输入：datasource_id + report_type
    输出：report (pdf/excel/md)
    """
    
    report_types = [
        "quality",        # 质量报告
        "knowledge",      # 知识库报告
        "insight",        # 洞察报告
        "comprehensive"   # 综合报告
    ]
```

## 6. 工作流设计（LangGraph）

### 数据处理工作流

```python
from langgraph.graph import StateGraph, END

workflow = StateGraph()

# 定义节点
workflow.add_node("upload", upload_data)
workflow.add_node("clean", clean_data_agent)
workflow.add_node("analyze", quality_assessment_agent)
workflow.add_node("extract", knowledge_extraction_agent)
workflow.add_node("report", report_generation_agent)

# 定义流程
workflow.set_entry_point("upload")
workflow.add_edge("upload", "clean")
workflow.add_edge("clean", "analyze")
workflow.add_edge("analyze", "extract")
workflow.add_edge("extract", "report")
workflow.add_edge("report", END)

# 编译
app = workflow.compile()
```

## 7. 安全设计

### 认证与授权

```
认证方式：
- JWT Token（access 60 分钟 + refresh 7 天，登出用 Redis 黑名单吊销）
- 不使用服务端 Session（无状态）

权限级别（详见 04-API设计.md 的「角色与接口权限」）：
- Admin：全部权限（含他人资源）
- User：管理自己的数据源 / 报告 / 任务
- Viewer：只读访问
```

### 数据安全

```
- API Key 加密存储
- 敏感数据脱敏
- HTTPS 传输
- SQL 注入防护
- XSS 防护
```

### 缓存策略

```
Redis 缓存：

## 9. 监控与日志

> 口径：**Loguru 日志 + 数据库 LLM 调用记录 + Prometheus 指标**（全部自建，不依赖第三方可观测 SaaS）。

### 日志（Loguru）

```
日志级别：
- DEBUG：开发环境
- INFO：生产环境
- ERROR：错误记录

输出：
- 控制台（开发）
- logs/app.log（滚动文件，配置项 LOG_FILE / LOG_LEVEL）

日志内容：
- API 请求/响应
- AI Agent 执行
- 数据库操作
- 异常堆栈
```

### LLM 调用记录（数据库）

```
落库字段（写入 analysis_results / cleaned_data 的 token_usage、cost、processing_duration）：
- agent_name / agent_version
- ai_model（来自 DEFAULT_LLM_MODEL）
- input_tokens / output_tokens
- duration / cost（按实际模型单价计算）
```

### 监控指标（Prometheus）

```
采集端点：METRICS_PATH（默认 /metrics，由 PROMETHEUS_ENABLED 控制）

系统指标：
- CPU/内存使用率
- API 响应时间
- 数据库连接数

业务指标：
- 数据处理量
- AI 调用次数 / token 用量
- 用户活跃度
```

## 10. 部署架构

### 开发环境

```
