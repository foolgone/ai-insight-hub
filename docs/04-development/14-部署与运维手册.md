# 部署与运维手册（B-704）

> 适用版本：后端 MVP v2.0（P0~P7 完成，2026-10-25）
> 事实源：`docs/04-development/12-后端开发计划.md`、`09-可观测与成本监控.md`、`13-ADR-001`

---

## 1. 部署架构

```
Nginx(:80) → API(FastAPI + Uvicorn, :8000)
                ├── PostgreSQL 14 + pgvector（业务库/向量）
                ├── Redis 7（限流 + JWT 黑名单 + Celery broker/backend）
                └── MinIO / 本地存储（上传文件、报告文件）
Celery worker（清洗/评估/提取/洞察/报告/成本对账） ← Redis
Celery beat（每日 00:05 成本对账）
```

## 2. 环境变量

以 `backend/.env.example` 为准，生产必须修改：

| 变量 | 说明 |
|---|---|
| `ENVIRONMENT` / `DEBUG` | 生产设为 `production` / `false` |
| `DATABASE_URL` | `postgresql://user:pass@postgres:5432/aiinsight`（代码内部转 asyncpg） |
| `REDIS_URL` | `redis://redis:6379/0` |
| `CELERY_BROKER_URL` / `CELERY_RESULT_BACKEND` | Redis db1 / db2 |
| `MINIO_ENDPOINT` / `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | 对象存储；不可用时 `STORAGE_BACKEND=auto` 回退本地 |
| `DEEPSEEK_API_KEY` | **只放服务器 .env，不入库、不提交** |
| `DEFAULT_LLM_MODEL` | 默认 `deepseek-flash` |
| `LLM_PRICE_INPUT_PER_MTOK` / `LLM_PRICE_OUTPUT_PER_MTOK` | 成本核算单价；为 0 时成本恒为 0（启动告警） |
| `DAILY_COST_LIMIT` / `MONTHLY_COST_LIMIT` | 成本预算（降级阈值 0.8/0.9/1.0/1.2） |
| `DEGRADED_LLM_MODEL` | 留空 = 不切模型，仅告警（D-09 当前口径） |
| `JWT_SECRET_KEY` | 必须替换为强随机值 |
| `BACKEND_CORS_ORIGINS` | 前端域名白名单 |
| `RATE_LIMIT_ENABLED` / `RATE_LIMIT_PER_MINUTE` | 限流开关与阈值 |

## 3. 部署步骤（Docker Compose）

```powershell
# 1) 准备环境变量
copy backend\.env.example backend\.env
# 编辑 backend\.env（见 §2）

# 2) 构建并启动（API 容器启动前自动 alembic upgrade head）
docker compose -f docker-compose.prod.yml up -d --build

# 3) 验证
docker compose -f docker-compose.prod.yml ps
curl http://localhost/health
curl http://localhost/api/v1/health
```

说明：
- `postgres`/`redis`/`minio` 均有 healthcheck，`api` 依赖其健康后启动；
- worker/beat 与 api 共用镜像，通过 `command` 覆盖启动命令；
- 迁移由 `backend/scripts/docker-entrypoint.sh` 统一执行，多副本 API 时只会重复执行幂等迁移；
- Nginx 仅暴露 `/api`、`/docs`、`/health` 与内网 `/metrics`。

## 4. 日常运维

| 操作 | 命令 |
|---|---|
| 查看 API 日志 | `docker compose -f docker-compose.prod.yml logs -f api` |
| 查看 worker 日志 | `docker compose -f docker-compose.prod.yml logs -f worker` |
| 手动迁移 | `docker compose exec api alembic upgrade head` |
| 回滚一次迁移 | `docker compose exec api alembic downgrade -1` |
| 健康检查 | `curl /health`（存活）、`curl /api/v1/health`（业务） |
| 指标 | 内网 `GET /metrics`（Prometheus 格式，`PROMETHEUS_ENABLED=false` 可关闭） |
| 成本对账 | 查 `llm_calls` 聚合（按天/用户/模型）；`tasks.monitor_cost` 每日 00:05 记录告警 |

### 4.1 成本对账口径

- **唯一口径**：`llm_calls`（成功调用 `status='success'`）按 `total_cost` 聚合；
- Prometheus（`llm_cost_usd_total` 等）只做实时趋势，**不能用于月结**；
- 单价为 0 时金额恒为 0：上线前必须由业务方提供 `LLM_PRICE_*`；
- 告警阈值：日预算 0.8 告警 / 0.9 限流 / 1.0 降级 / 1.2 停止。

### 4.2 数据备份

- PostgreSQL：每日 `pg_dump -Fc`（含 `vector` 扩展数据）；
- MinIO：启用版本或定期 `mc mirror` 至备份桶；
- Redis：可重建（限流计数/队列），黑名单丢失会导致已登出 token 在过期前仍可用，安全要求高时需持久化。

### 4.3 Worker 运行与嵌入模型

- **Windows 本地**：Celery 需用 solo 池：`celery -A app.core.celery:celery_app worker -l info --pool=solo`；
- **任务隔离**：每个 Celery 任务在独立事件循环中执行，服务层会在任务结束后 `dispose_engine()`，避免 asyncpg 连接跨事件循环复用（`Event loop is closed`）；
- **嵌入模型离线**：服务器无法访问 huggingface.co 时，需提前把模型缓存到 `EMBEDDING_CACHE_DIR`，并给 worker 设置：
  `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`；模型不可用时知识提取会降级为「无向量」入库，检索自动走 pg_trgm；
- 首次部署建议在联网机器上下载模型后整体拷贝缓存目录。

## 5. 故障排查

| 现象 | 排查 |
|---|---|
| 容器启动即退出 | `logs api` 看迁移失败/环境变量缺失 |
| 401 集中出现 | JWT 密钥变更、系统时间偏差、Redis 黑名单服务不可用 |
| 429 集中出现 | 限流（60/min）或成本 STOPPED（看 `X-Cost-Status`） |
| 任务一直 pending | worker 未启动 / Redis broker 不通 |
| 报告下载 404 | 报告未 completed 或对象存储文件丢失 |
| 检索无结果 | 嵌入模型未加载（降级为 pg_trgm）或知识库为空（三态提示） |

## 6. 已知限制（v2.0）

1. `LLM_PRICE_*` 默认 0，成本金额需业务方给价后才有意义；
2. `DEGRADED_LLM_MODEL` 留空：降级只告警、不切模型（D-09）；
3. 报告仅支持 markdown/excel（无 weasyprint，pdf/html 返回 422，D-11 降级方案）；
4. Prompt 金标准语义基线待首次真实跑批生成（结构测试已就绪）；
5. 本地/VM 环境 MinIO 常不可用，自动回退本地 `.storage/`；
6. 性能压测脚本已就绪，**100 并发基线未在本机执行**（需独立压测环境）；
7. Docker 镜像构建需 Docker daemon；当前 CI 仅做 compose 配置校验；
8. `api_keys` / `webhooks` 属 MVP 之外（B-706 不做）。
