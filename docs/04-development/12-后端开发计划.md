## 0. 一页速览

**一句话**：先把「契约 + 数据 + Agent 基座 + 成本可观测」四块地基打牢，再按 清洗 → 评估 → 知识 → 报告 → 洞察 → 工作流 的数据依赖顺序实现 5 个 Agent，每个功能与测试同批交付。

**当前基线**：环境（VM PostgreSQL 14 + pgvector / Redis）、项目骨架、配置事实源、Alembic 骨架、pytest 骨架、CI 已就绪；**业务代码为 0**（0 张业务表、0 个迁移、0 个 API、0 个 Agent、0 份 Prompt 资产）。

**关键路径（不可压缩）**：

```
环境修复 → 决策冻结 → POC(模型/向量/工作流/成本) → DB 模型+迁移 → 成本底座 → BaseAgent
        → 清洗 Agent → 评估 Agent → 提取 Agent → 报告 Agent → 自研编排器 → 集成测试 → 上线
```

**里程碑（对齐 `04-开发方案.md` §2）**：

| 里程碑 | 文档周次 | 后端交付物 | 阶段 |
|---|---|---|---|
| M1 环境就绪 | Week 1 | ✅ 已完成（骨架 + VM 数据库接入） | — |
| M2 POC 完成 | Week 2 | 4 项 POC 代码 + POC 报告 + 参数冻结建议 | P1 |
| M3 基础架构 | Week 4 | 15 张表 + 6 个迁移 + 认证/RBAC + 契约横切 + 测试基建 | P2 |
| M4 数据清洗 | Week 6 | 数据源 CRUD + 上传 + 任务 + 清洗 Agent（端到端可跑） | P3 |
| M5 质量评估 | Week 8 | 评估 Agent（5 维）+ 评估 API + 人工复核分支 | P4 |
| M6 知识提取 | Week 10 | 提取 Agent + 冷启动 + 知识库 API + 基础报告 | P5 |
| M7 MVP 完成 | Week 12 | 洞察 Agent + 自研编排器 + 端到端链路 | P6 |
| M8 上线就绪 | Week 14 | 性能/安全/可观测收口 + 部署产物 + 文档 | P7 |

**开工前必须先解决**（详见 §2.3 / §4.2）：单价与降级模型未冻结、`BaseAgent` 有三份互不兼容草案、`agent_failures`/`cost_tracking` 表名残留、venv 缺 8 个包、`env.py` 的 `target_metadata=None`。

### 5.2 阶段详述

#### P0 决策与环境（W1 前半）

- **目标**：把「会返工的事」在写第一行业务代码前排掉。
- **交付物**：环境自检报告、决策记录（追加到本文档 §4.2 的「已拍板」列）、`develop` 分支与任务看板、契约冻结草案（错误码/响应包/分页/RBAC 矩阵）。
- **出口**：`pytest -m "not prompt"` 绿；`alembic upgrade head` 不再报 metadata 缺失（此时可为空迁移）；D-01/D-02/D-03/D-09/D-12 均有结论。

#### P1 技术验证（W2 / M2）

- **目标**：用最小代码证明四件事：DeepSeek 能调（自研客户端）、384 维向量能写能搜、自研编排能跑、token/成本能记录。
- **交付物**：`tests/poc/` 下 4 个 POC 脚本 + `POC 验证报告`（填 `04-开发方案` §4.3 模板，不得预填结论）。
- **出口**：报告含实测数据（JSON 解析失败率、1 万/10 万条检索耗时、编排分支、token 与成本核对）；据此冻结 `DEFAULT_LLM_MODEL` 真实值、单价占位与降级候选模型。
- **注意**：POC 不进入主 CI（`-m "not prompt"` 排除，脚本打 `slow` 或独立目录）。

#### P2 基础架构（W3-4 / M3）

- **目标**：一次性把「表 + 迁移 + 底座 + 契约 + 认证 + 测试基建」立起来，后续所有功能只做加法。
- **交付物**：15 张表模型 + 6 个迁移（001 扩展/users/data_sources → 002 数据管道 4 表 → 003 业务支撑 5 表 → 004 Prompt 3 表 → 005 `llm_calls` → 006 种子管理员）；异常体系/日志/指标/DB 会话/Schema 基类/分页限流/认证/RBAC；测试三层骨架；CI 对齐。
- **出口**：VM 上 `alembic upgrade head`/`downgrade` 双向通过；`/docs` 可见认证与用户端点；`pytest --cov=fail-under=80` 绿；`llm_calls` 表可写入（手工验证）。

#### P3 数据源 + 清洗（W5-6 / M4）

- **目标**：首个端到端业务闭环——建数据源 → 上传文件 → 入队清洗 → 出 `cleaned_data`。
- **交付物**：数据源 CRUD + 配额、任务 5 态、Celery、文件解析与存储、成本/重试/降级/结构化四件套、`BaseAgent`、清洗 Agent + 工具 + Prompt、清洗结果 API。
- **出口**：一条 CSV 从上传到清洗结果可查；`llm_calls` 有记录、成本可算；失败任务可 `retry`；清洗 Prompt 测试 ≥50 条。

#### P4 质量评估（W7-8 / M5）

- **目标**：对清洗后对话做 5 维评估，低分进入人工复核分支。
- **交付物**：评估 Agent + 5 维度 Prompt + 评估 API + `analysis_results` 落库 + `manual_review` 触发与回写。
- **出口**：5 维权重与归一化符合 Agent 设计示例（5 维全开口径）；阈值 70 双口径生效；知识库为空时 hallucination 走 70 分降级；评估 Prompt 测试 ≥50。

#### P5 知识提取 + 报告（W9-10 / M6）

- **目标**：从对话中沉淀 FAQ、发现盲区，并产出第一份可下载报告。
- **交付物**：冷启动三态 + 种子库 + 嵌入服务 + 提取 Agent + 知识库 API（FAQ CRUD/search/gaps）+ 报告 Agent + 报告模板 + 报告 API。
- **出口**：空库/冷启动/就绪三态响应正确；`knowledge_base` 384 维写入与 HNSW 检索可用；报告 `generating→completed` 状态机与文件可下载；提取 Prompt 测试 ≥50。

#### P6 洞察 + 工作流 + 集成测试（W11-12 / M7）

- **目标**：5 个 Agent 串成一条可重放的工作流，端到端验收 MVP。
- **交付物**：洞察 Agent + 洞察 API（P1）+ 自研编排器（6 步 + 条件分支 + 每步落 `tasks`）+ 端到端集成测试 + Prompt 测试补齐 + 可观测收口。
- **出口**：工作流一次运行产出清洗/评估/知识/报告全链路数据；`overall_score<70` 能走 `manual_review` 再回主链；5 个 Agent 的 Prompt 测试均 ≥50/维度 ≥10；指标与成本告警可用。

#### P7 上线准备（W13-14 / M8）

- **目标**：从「能跑」到「可上线」。
- **交付物**：性能测试报告（100 并发、检索延迟、成本）、安全测试报告、Dockerfile + `docker-compose.prod.yml`（+ Nginx 可选）、文档回写（README/运维手册/API 文档/POC 报告）、上线验收清单。
- **出口**：对照 `06-testing` 与 `09-可观测` 的验收清单逐项打勾；`docs/07-review` 的 R-1~R-5 已回写；P2 功能（API Key/Webhook）明确取舍。

## 7. 依赖关系与关键路径

**关键路径**（任一延期即整体延期）：

```
B-001 → B-002(D-01/02/03/09/12) → B-101~B-105 → B-200
      → B-203 → B-204 → B-205 → B-306 → B-307/B-308 → B-310
      → B-313 → B-401 → B-504 → B-508 → B-604 → B-606 → B-701 → B-703 → B-705
```

**可并行窗口**：

1. **API 线与成本线并行**（B-206 完成后）：B-208~B-212（认证/用户/契约）∥ B-306~B-309（成本/重试/降级/结构化），两者只在 B-310 汇合。
2. **冷启动线与评估线并行**（M5）：B-501/B-502/B-503 只依赖表与 `BaseAgent`，可与 B-401~B-405 并行。
3. **报告与洞察并行**（M6）：B-601~B-603（洞察）∥ B-508~B-510（报告），在 B-604 工作流处汇合。
4. **Prompt 资产与 Agent 代码同人同批**：避免 Schema 与 Prompt 脱节（B-312/B-402/B-505/B-602）。
5. **前端契约线**：B-212 完成后前端即可按 OpenAPI 开发，不必等后端全部实现。

**顺序纪律**（违反会返工）：

- 先「契约」后「业务」：错误码/响应包/分页/RBAC 先冻结。
- 先「任务状态机」后「清洗/评估/提取/报告」：所有异步接口都依赖 `tasks`。
- 先「成本+重试+降级」后「任何 Agent」：四件套挂在 `BaseAgent` 上。
- 先「数据源 CRUD」后「所有 `/datasources/{id}/…` 子资源」：它是路径父节点与归属校验落点。
