## 1. 问题描述

### 当前问题

原有成本管理文档提到了预警和限流，但没有明确：

❌ 成本达到限额后的具体行为  
❌ 是完全停止服务还是降级？  
❌ 降级的具体策略是什么？  
❌ 如何通知用户？  

### 影响

- 可能导致服务完全中断，影响用户体验
- 用户不知道为什么服务突然不可用
- 没有缓冲机制，要么正常要么停止

## 2. 降级策略设计

### 2.1 四级降级策略

```
┌────────────────────────────────────────────────┐
│  成本使用情况      │  阈值  │  动作            │
├────────────────────────────────────────────────┤
│  正常使用          │  < 0.80│  ✅ 正常服务     │
│  接近限额          │  0.80  │  ⚠️  预警通知    │
│  达到限额          │  0.90  │  🔶 开始限流     │
│  超出限额          │  1.00  │  🔻 降级服务     │
│  严重超限          │  1.20  │  🛑 停止服务     │
└────────────────────────────────────────────────┘
```

> 阈值定义与判定顺序见 `03-成本管理.md` §5.1（`warning` / `throttled` / `degraded` / `stopped`），本文只描述各档位的**动作**，不重复定义数值。

---

### 2.2 详细降级规则

#### 阶段 1: 正常服务 (< 0.80)

```text
状态: "normal"
行为:
  - ✅ 使用主模型（settings.DEFAULT_LLM_MODEL，当前为 "deepseek-v4.1-flash"）
  - ✅ 无限流
  - ✅ 全部功能可用
  - ✅ 无降级
```

---

#### 阶段 2: 预警通知 (0.80-0.90)

```text
状态: "warning"
行为:
  - ⚠️  发送预警邮件/站内通知
  - ✅ 服务正常运行
  - 📊 增加成本监控频率（每 10 分钟检查）

通知内容:
  "您的今日成本已达到 {usage_pct}%（约 ${current_cost} / ${daily_limit}）
   请注意控制使用，避免服务受限"
  # current_cost 由 llm_calls 表按 token × 单价聚合得出，非硬编码
```

---

#### 阶段 3: 开始限流 (0.90-1.00)

```text
状态: "throttled"
行为:
  - 🔶 降低 QPS 限制（从 60 → 30 请求/分钟）
  - ✅ 继续使用主模型
  - ✅ 核心功能可用
  - ⏸️  非核心功能（报告生成）排队处理

响应头添加:
  X-RateLimit-Remaining: 30
  X-RateLimit-Reset: 1698076800
  X-Cost-Usage: "0.92"
  X-Cost-Status: "throttled"
```

---

#### 阶段 4: 降级服务 (1.00-1.20)

```text
状态: "degraded"
行为:
  - 🔻 切换到降级模型（settings.DEGRADED_LLM_MODEL，型号待确认）
  - 🔻 QPS 限制进一步降低（30 → 10 请求/分钟）
  - ⏸️  暂停后台任务（批量处理、定时报告）
  - ✅ 核心功能保持可用（数据清洗、评估）
  - 🧩 结构化输出兜底：schema 校验 → 一次修复重试 → 转人工（见 §3.5）

用户提示:
  "您的成本配额已用尽，当前使用经济模式
   功能可能受限，建议升级套餐或明日再试"
```

**模型降级对比（定性）**：

| 维度 | 主模型 `DEFAULT_LLM_MODEL` | 降级模型 `DEGRADED_LLM_MODEL` | 影响 |
|------|---------------------------|------------------------------|------|
| 成本 | 按 `P_IN` / `P_OUT` 计 | 单价更低（具体型号与单价**待确认**） | 省多少需按 §0 公式实测 |
| 速度 | 基准 | 通常更快 | 待实测 |
| 结构化输出准确率 | 基准 | 可能下降 | 需 POC 的 JSON schema 校验通过后才可上线 |

> 历史版本中的「省 73% / 3.7 倍 / 准确率 95%→85%」均为无来源估算，已删除。降级型号冻结前，只做定性判断。

---

#### 阶段 5: 停止服务 (>= 1.20)

```text
状态: "stopped"
行为:
  - 🛑 停止所有 AI 调用
  - ✅ 基础功能可用（查看历史数据）
  - ❌ 无法创建新任务
```

错误响应（HTTP 429）：

```json
{
  "error": "DAILY_COST_LIMIT_EXCEEDED",
  "message": "您的每日成本限额已超限，服务已暂停",
  "current_cost": 132.5,
  "daily_limit": 100.0,
  "reset_at": "2026-10-24T00:00:00Z",
  "suggestion": "请升级套餐或等待明日重置"
}
```

> `132.5 / 100.0` 仅为示例数值，实际由配额配置与 `llm_calls` 聚合得出。

## 3. 实现方案

### 3.1 降级策略配置

```python
# app/core/degradation.py
from enum import Enum
from typing import Any, Dict

from app.core.config import settings
from app.core.cost_alerts import CostAlertManager


class DegradationLevel(Enum):
    """降级级别"""
    NORMAL = "normal"
    WARNING = "warning"
    THROTTLED = "throttled"
    DEGRADED = "degraded"
    STOPPED = "stopped"


class DegradationConfig:
    """降级配置

    阈值直接复用 CostAlertManager.ALERT_THRESHOLDS（见 03-成本管理.md §5.1），
    避免两处数字漂移。
    """

    THRESHOLDS = {
        DegradationLevel.WARNING: CostAlertManager.ALERT_THRESHOLDS["warning"],    # 0.80
        DegradationLevel.THROTTLED: CostAlertManager.ALERT_THRESHOLDS["throttled"],  # 0.90
        DegradationLevel.DEGRADED: CostAlertManager.ALERT_THRESHOLDS["degraded"],   # 1.00
        DegradationLevel.STOPPED: CostAlertManager.ALERT_THRESHOLDS["stopped"],     # 1.20
    }

    # 主模型与降级模型均来自配置，型号变更不需要改代码
    PRIMARY_MODEL = settings.DEFAULT_LLM_MODEL
    DEGRADED_MODEL = settings.DEGRADED_LLM_MODEL

    ACTIONS = {
        DegradationLevel.NORMAL: {
            "model": PRIMARY_MODEL,
            "qps_limit": 60,
            "features": ["all"],
            "background_tasks": True
        },
        DegradationLevel.WARNING: {
            "model": PRIMARY_MODEL,
            "qps_limit": 60,
            "features": ["all"],
            "background_tasks": True,
            "notify": True
        },
        DegradationLevel.THROTTLED: {
            "model": PRIMARY_MODEL,
            "qps_limit": 30,
            "features": ["all"],
            "background_tasks": True
        },
        DegradationLevel.DEGRADED: {
            "model": DEGRADED_MODEL,  # 降级模型（型号待确认）
            "qps_limit": 10,
            "features": ["clean", "evaluate"],  # 只保留核心功能
            "background_tasks": False  # 暂停后台任务
        },
        DegradationLevel.STOPPED: {
            "model": None,
            "qps_limit": 0,
            "features": [],  # 无 AI 功能
            "background_tasks": False
        }
    }
```

> ⚠️ `settings.DEGRADED_LLM_MODEL` 目前尚未写入 `backend/app/core/config.py`，属于**待确认配置项**（需与主模型一同冻结型号与单价）。

### 3.2 降级管理器

```python
# app/core/degradation_manager.py
from datetime import datetime, timedelta
from typing import Any, Dict

from loguru import logger

from app.core.degradation import DegradationConfig, DegradationLevel


class DegradationManager:
    """降级管理器"""

    def __init__(self, cost_tracker, redis_client, user_repo):
        self.cost_tracker = cost_tracker
        self.redis = redis_client
        self.user_repo = user_repo

    async def get_degradation_level(self, user_id: str) -> DegradationLevel:
        """获取当前降级级别"""

        # 1. 获取用户配额和使用情况
        user = await self.user_repo.get(user_id)
        daily_limit = (user.quota or {}).get("daily_cost_limit", 0)

        # 2. 获取今日成本（由 llm_calls 聚合，已按 token × 单价计算）
        today_cost = await self.cost_tracker.get_daily_cost(user_id)

        # 3. 计算使用比例（限额非正数时不做降级判断）
        if daily_limit <= 0:
            return DegradationLevel.NORMAL
        usage_ratio = today_cost / daily_limit

        # 4. 确定降级级别
        thresholds = DegradationConfig.THRESHOLDS
        if usage_ratio >= thresholds[DegradationLevel.STOPPED]:
            return DegradationLevel.STOPPED
        if usage_ratio >= thresholds[DegradationLevel.DEGRADED]:
            return DegradationLevel.DEGRADED
        if usage_ratio >= thresholds[DegradationLevel.THROTTLED]:
            return DegradationLevel.THROTTLED
        if usage_ratio >= thresholds[DegradationLevel.WARNING]:
            return DegradationLevel.WARNING
        return DegradationLevel.NORMAL

    async def get_degradation_config(self, user_id: str) -> Dict[str, Any]:
        """获取降级配置"""

        level = await self.get_degradation_level(user_id)
        config = DegradationConfig.ACTIONS[level].copy()

        # 添加额外信息
        today_cost = await self.cost_tracker.get_daily_cost(user_id)
        user = await self.user_repo.get(user_id)
        daily_limit = (user.quota or {}).get("daily_cost_limit", 0)
        usage_ratio = today_cost / daily_limit if daily_limit > 0 else 0.0

        config.update({
            "level": level.value,
            "usage_ratio": usage_ratio,
            "current_cost": today_cost,
            "daily_limit": daily_limit,
            "reset_at": self._get_reset_time()
        })

        return config

    def _get_reset_time(self) -> datetime:
        """获取重置时间（明天凌晨）"""
        tomorrow = datetime.now() + timedelta(days=1)
        return tomorrow.replace(hour=0, minute=0, second=0, microsecond=0)

    async def should_use_degraded_model(self, user_id: str) -> bool:
        """是否应该切换到降级模型"""
        level = await self.get_degradation_level(user_id)
        return level == DegradationLevel.DEGRADED

    async def is_service_stopped(self, user_id: str) -> bool:
        """服务是否已停止"""
        level = await self.get_degradation_level(user_id)
        return level == DegradationLevel.STOPPED
```

> 说明：`get_daily_cost` 在 `03-成本管理.md` §3.2 的 `CostTracker` 中实现；本类不再自行拼接 SQL。

### 3.3 中间件集成

```python
# app/middleware/degradation_middleware.py
from fastapi import Request
from fastapi.responses import JSONResponse
from starlette.middleware.base import BaseHTTPMiddleware

from app.core.degradation import DegradationLevel

# 不参与降级判定的路径（探活、静态资源、文档）
EXEMPT_PATHS = ("/health", "/metrics", "/docs", "/openapi.json")


class DegradationMiddleware(BaseHTTPMiddleware):
    """降级中间件"""

    async def dispatch(self, request: Request, call_next):
        # 0. 探活/静态路径直接放行
        if request.url.path in EXEMPT_PATHS:
            return await call_next(request)

        # 1. 获取用户
        user_id = getattr(request.state, "user_id", None)

        if not user_id:
            return await call_next(request)

        # 2. 检查降级状态
        degradation_manager = request.app.state.degradation_manager
        config = await degradation_manager.get_degradation_config(user_id)

        # 3. 如果服务已停止
        #    注意：中间件里抛 HTTPException 不会被 ExceptionMiddleware 捕获，
        #    这里直接返回 JSONResponse，避免变成 500。
        if config["level"] == DegradationLevel.STOPPED.value:
            return JSONResponse(
                status_code=429,
                content={
                    "error": "DAILY_COST_LIMIT_EXCEEDED",
                    "message": "您的每日成本限额已超限，服务已暂停",
                    "current_cost": config["current_cost"],
                    "daily_limit": config["daily_limit"],
                    "reset_at": config["reset_at"].isoformat(),
                    "suggestion": "请升级套餐或等待明日重置",
                },
                headers={"Retry-After": "3600"},
            )

        # 4. 添加降级信息到请求状态
        request.state.degradation_config = config

        # 5. 执行请求
        response = await call_next(request)

        # 6. 添加降级信息到响应头
        response.headers["X-Cost-Usage"] = f"{config['usage_ratio']:.1%}"
        response.headers["X-Cost-Status"] = config["level"]
        response.headers["X-Cost-Reset"] = config["reset_at"].isoformat()

        if config["level"] in ("throttled", "degraded"):
            response.headers["X-RateLimit-Limit"] = str(config["qps_limit"])

        return response


# 在 main.py 中注册（需在鉴权中间件之后，保证 request.state.user_id 已写入）
# app.add_middleware(DegradationMiddleware)
```

### 3.4 Agent 集成降级

```python
# app/agents/base.py
from loguru import logger

from app.core.config import settings
from app.core.degradation import DegradationLevel
from app.core.exceptions import ServiceUnavailableError


class BaseAgent:
    """Agent 基类（集成降级）"""

    def __init__(self, degradation_manager, llm_factory):
        self.degradation_manager = degradation_manager
        self.llm_factory = llm_factory

    async def invoke(self, input_data: dict, user_id: str | None = None) -> dict:
        """执行 Agent（自动降级）"""

        if not user_id:
            # 没有用户 ID，走主模型默认配置
            return await self._execute(input_data, model=settings.DEFAULT_LLM_MODEL)

        # 1. 获取降级配置
        config = await self.degradation_manager.get_degradation_config(user_id)

        # 2. 检查服务是否停止
        if config["level"] == DegradationLevel.STOPPED.value:
            raise ServiceUnavailableError("成本限额已超限，服务暂停")

        # 3. 选择模型（来自配置，不写死型号）
        model = config["model"]

        # 4. 执行
        if config["level"] == DegradationLevel.DEGRADED.value:
            logger.warning(
                "user {} 进入降级服务，使用模型 {}", user_id, model
            )

        result = await self._execute(input_data, model=model)

        # 5. 在结果中标注降级信息
        result["_degradation"] = {
            "level": config["level"],
            "model_used": model,
            "is_degraded": config["level"] in (
                DegradationLevel.DEGRADED.value,
                DegradationLevel.THROTTLED.value,
            ),
        }

        return result
```

### 3.5 降级后的结构化输出兜底

降级模型更小，结构化输出（JSON）更容易出现字段缺失、类型错误、多余文本。降级期间必须走「校验 → 修复 → 转人工」三级兜底，**不允许把不合法 JSON 直接入库**。

```python
# app/agents/structured_output.py
import json
from typing import Any, Type, TypeVar

from loguru import logger
from pydantic import BaseModel, ValidationError

T = TypeVar("T", bound=BaseModel)

REPAIR_PROMPT = """你上一次的输出不是合法 JSON 或不符合 schema。
请只输出合法 JSON，不要包含解释、Markdown 代码块或额外文本。
校验错误：{error}
原始输出：{raw}
"""


class StructuredOutputError(Exception):
    """两次尝试后仍无法得到合法结构化输出"""


async def parse_with_repair(
    llm,
    prompt: str,
    schema: Type[T],
    max_attempts: int = 2,
) -> T:
    """解析结构化输出：首次失败后用一次修复重试，仍失败则抛出异常转人工。"""

    raw = await llm.ainvoke(prompt)
    text = getattr(raw, "content", str(raw))

    last_error: Exception | None = None
    for attempt in range(1, max_attempts + 1):
        try:
            return schema.model_validate_json(text)
        except (ValidationError, json.JSONDecodeError) as exc:
            last_error = exc
            logger.warning("结构化输出校验失败（第 {} 次）：{}", attempt, exc)
            if attempt == max_attempts:
                break
            raw = await llm.ainvoke(
                REPAIR_PROMPT.format(error=exc, raw=text)
            )
            text = getattr(raw, "content", str(raw))

    # 兜底：转人工，不写库
    raise StructuredOutputError(
        f"结构化输出连续 {max_attempts} 次不合法，已转人工处理：{last_error}"
    )
```

> 转人工后的记录写入 `llm_calls`（`status='failed'`，`attempt` 记录实际次数），并在前端任务详情里标记「需人工复核」。

```python
    """监控所有用户的成本（每 10 分钟运行）

    Celery worker 是同步进程，内部用 asyncio.run 驱动异步逻辑，
    不要直接给 task 加 async def（否则拿到的是 coroutine，不会执行）。
    """
    import asyncio

    asyncio.run(_monitor_user_costs_async())


async def _monitor_user_costs_async():
    degradation_manager = DegradationManager(...)

    # 获取所有活跃用户
    active_users = await get_active_users()

    for user in active_users:
        level = await degradation_manager.get_degradation_level(user.id)

        # 检查是否需要发送通知
        if level == DegradationLevel.WARNING:
            # 只在第一次达到 80% 时通知

                await send_warning_notification(user)
                await mark_warning_sent(user.id)

        elif level == DegradationLevel.DEGRADED:
            # 达到 100% 时通知
            if not await has_sent_degraded_notification(user.id):
                await send_degraded_notification(user)
                await mark_degraded_sent(user.id)

        elif level == DegradationLevel.STOPPED:
            # 超过 120% 时通知
            if not await has_sent_stopped_notification(user.id):
                await send_stopped_notification(user)
                await mark_stopped_sent(user.id)
```

```python
class AlertService:

            当成本达到：
            - 80%：仅预警，服务正常
            - 90%：开始限流（QPS 降低 50%）
            - 100%：切换到降级模型（DEGRADED_LLM_MODEL，型号待确认）
            - 120%：暂停服务
            
            建议：
            1. 优化 Prompt 以减少 Token 使用
            2. 使用缓存避免重复调用
            3. 升级到更高套餐
            
            --
            AI Insight Hub 团队
            """
        )
        
        # 2. 站内通知
        await create_notification(
            user_id=user.id,
            type="cost_warning",
            title="成本预警",
            content=f"今日成本已达 {config['usage_ratio']:.1%}，请注意控制",
            level="warning"
        )
        
        # 3. Webhook（如果配置）
        if user.webhook_url:
            await send_webhook(
                url=user.webhook_url,
                data={
                    "event": "cost_warning",
                    "user_id": user.id,
                    "usage_ratio": config['usage_ratio'],
                    "current_cost": config['current_cost'],
                    "daily_limit": config['daily_limit']
                }
            )
```

```jsx
import { useEffect, useState } from 'react';

import { getCostStatus } from '../api/user';

export function CostWarningBanner() {
  const [costStatus, setCostStatus] = useState(null);

  useEffect(() => {
    let cancelled = false;

    const load = async () => {
      try {
        const status = await getCostStatus();
        if (!cancelled) setCostStatus(status);
      } catch {
        // 成本状态查询失败不阻塞主流程
      }
    };

    load(); // 挂载后立即查一次
    const interval = setInterval(load, 60000); // 之后每分钟一次

    return () => {
      cancelled = true;
      clearInterval(interval);
    };
  }, []);

  if (!costStatus || costStatus.level === 'normal') {
    return null;
  }

  // 后端返回 snake_case，经 axios 拦截器后为 camelCase（见 05-API命名规范.md）
  const usagePercent = ((costStatus.usageRatio ?? 0) * 100).toFixed(1);

  return (
    <div className={`banner banner-${costStatus.level}`}>
      {costStatus.level === 'warning' && (
        <div className="bg-yellow-100 border-l-4 border-yellow-500 p-4">
          <p className="text-yellow-700">
            ⚠️ 成本预警：今日已使用 {usagePercent}% 配额
          </p>
        </div>
      )}

      {costStatus.level === 'throttled' && (
        <div className="bg-orange-100 border-l-4 border-orange-500 p-4">
          <p className="text-orange-700">
            🔶 服务限流：已达配额 {usagePercent}%，请求速率已降低
          </p>
        </div>
      )}

      {costStatus.level === 'degraded' && (
        <div className="bg-red-100 border-l-4 border-red-500 p-4">
          <p className="text-red-700">
            🔻 经济模式：配额已用尽，当前使用降级模型，功能可能受限
          </p>
          <button type="button" onClick={() => { window.location.href = '/upgrade'; }}>
            升级套餐
          </button>
        </div>
      )}

      {costStatus.level === 'stopped' && (
        <div className="bg-red-600 text-white p-4">
          <p className="font-bold">
            🛑 服务已暂停：配额严重超限，AI 功能暂时不可用
          </p>
          <p>将于 {new Date(costStatus.resetAt).toLocaleString()} 恢复</p>
          <button type="button" onClick={() => { window.location.href = '/upgrade'; }}>
            立即升级
          </button>
        </div>
      )}
    </div>
  );
}
```

> ⚠️ `@/` 别名在 `frontend/vite.config.js` 中**未配置**（只有 `server.proxy`），因此这里用相对路径。若要启用 `@/`，需补 `resolve.alias`。

## 📊 降级效果预估

### 成本节省

> 下表只描述**机制**，不写死金额与节省比例。具体节省额 = 两档单价差 × 实际 token 量，须在 `DEGRADED_LLM_MODEL` 与两档单价冻结后按 `03-成本管理.md` §0 公式测算。

| 阶段 | 成本区间（占限额比例） | 模型 | 机制上的节省来源 |
|------|----------------------|------|-----------------|
| 正常 | 0 – 0.80 | `DEFAULT_LLM_MODEL` | - |
| 预警 | 0.80 – 0.90 | `DEFAULT_LLM_MODEL` | - |
| 限流 | 0.90 – 1.00 | `DEFAULT_LLM_MODEL` | QPS 降低，减少并发调用量 |
| 降级 | 1.00 – 1.20 | `DEGRADED_LLM_MODEL` | 单价更低 + 暂停后台任务；**节省比例待实测** |
| 停止 | >= 1.20 | - | 停止 AI 调用，边际成本归零 |

**关键收益**：
- 降级后单条成本由「降级模型单价」决定，能多处理多少数据取决于两档单价之比（**待确认**）
- 避免服务完全中断
- 结构化输出有校验兜底，降级不等于降质到不可用

> 历史版本中的「省 73% / 多处理 3.7 倍」基于 Claude Sonnet/Haiku 的旧单价，已随模型切换作废。
