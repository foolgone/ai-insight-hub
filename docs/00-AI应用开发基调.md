## 📜 核心原则

### 1. Agent-First 思维 🤖

**AI Agent 是一等公民，不是辅助工具**

```
传统开发：业务逻辑 + AI 辅助
AI 应用开发：AI Agent + 业务编排
```

**具体实践：**
- ✅ 核心能力由 Agent 实现（清洗、评估、提取、分析）
- ✅ 业务逻辑是 Agent 编排和协调
- ✅ Agent 可独立测试、优化、替换
- ❌ 不要把 AI 当成"调用的函数"
- ❌ 不要把 Prompt 硬编码在业务代码中

**架构体现：**
```python
# ❌ 错误：AI 作为辅助
def clean_data(data):
    # 100 行业务逻辑
    result = llm.chat(f"Clean this: {data}")  # AI 只是工具
    # 再 100 行业务逻辑
    return result

# ✅ 正确：Agent 为核心
from langchain_deepseek import ChatDeepSeek
from langgraph.prebuilt import create_react_agent

from app.core.config import settings


class DataCleaningAgent:
    """独立的数据清洗 Agent"""

    def __init__(self, tools=None):
        # 模型 id 不写死在代码里，统一从 .env 的 DEFAULT_LLM_MODEL 读取
        self.llm = ChatDeepSeek(
            model=settings.DEFAULT_LLM_MODEL,          # 默认 deepseek-flash
            temperature=settings.DEFAULT_TEMPERATURE,  # 结构化任务默认 0
        )
        self.tools = tools or []
        self.agent = create_react_agent(self.llm, self.tools)

    def clean(self, data):
        return self.agent.invoke({
            "messages": [{"role": "user", "content": data}]
        })
```

### 4. 可观测性优先 (Observability-First) 👁️

**AI 是黑盒，必须可观测**

**监控维度：**
```
1. Token 使用量
   - 每个 Agent 的 Token 消耗
   - 成本追踪（单次请求成本 = token 用量 × 实际单价）
   
2. 性能指标
   - 响应时间（P50, P95, P99）
   - 吞吐量（QPS）
   
3. 质量指标
   - Agent 输出准确率
   - 用户满意度
   - 错误率
   
4. Agent 行为
   - Prompt 版本
   - 工具调用链路
   - 决策过程（CoT）
```

**工具选择（全部自建，不引入外部 SaaS 追踪平台）：**
- **Loguru 结构化日志** - 每次 Agent / LLM 调用的结构化事件日志
- **数据库 LLM 调用记录** - 每次调用的 token 用量、耗时、成本落库（`cost_tracking` 表）
- **Prometheus + Grafana** - 系统与业务指标采集与看板（`/metrics`）

对应配置项见 `backend/.env.example`：`LOG_LEVEL`、`LOG_FILE`、`LLM_CALL_LOG_ENABLED`、`PROMETHEUS_ENABLED`、`METRICS_PATH`。

**代码示例：**
```python
from app.core.config import settings
from app.core.db import db
from app.core.observability import llm_calls_total, llm_latency_seconds, llm_tokens_total
from loguru import logger


def track_llm_call(agent_name: str, result, elapsed: float) -> None:
    """一次 LLM 调用的可观测记录：结构化日志 + 数据库落库 + Prometheus 指标"""
    usage = result.response_metadata["token_usage"]
    input_tokens = usage["prompt_tokens"]
    output_tokens = usage["completion_tokens"]

    # 1. 结构化日志（Loguru）
    logger.bind(
        agent=agent_name,
        model=settings.DEFAULT_LLM_MODEL,
        input_tokens=input_tokens,
        output_tokens=output_tokens,
        elapsed_seconds=elapsed,
    ).info("llm_call")

    # 2. 数据库 LLM 调用记录（cost_tracking 表；成本=token 用量 × 实际单价）
    db.insert_cost_record(
        service="deepseek",
        model=settings.DEFAULT_LLM_MODEL,
        agent_name=agent_name,
        input_tokens=input_tokens,
        output_tokens=output_tokens,
        duration=elapsed,
    )

    # 3. Prometheus 指标（自建 /metrics）
    llm_calls_total.labels(agent=agent_name, model=settings.DEFAULT_LLM_MODEL).inc()
    llm_tokens_total.labels(agent=agent_name, kind="input").inc(input_tokens)
    llm_tokens_total.labels(agent=agent_name, kind="output").inc(output_tokens)
    llm_latency_seconds.labels(agent=agent_name).observe(elapsed)
```

### 5. Human-in-the-Loop (HITL) 🤝

**AI 不是 100% 准确，人类审核是必要的**

**具体实践：**
- ✅ 低置信度结果 → 人工审核队列
- ✅ 批量审核界面
- ✅ 审核反馈 → 模型微调
- ✅ 异常检测 → 自动预警

**工作流设计：**
```
AI Agent 输出
    ↓
置信度评估
    ↓
    ├─ 高置信度 (>90%) → 自动通过
    ├─ 中置信度 (70-90%) → 人工审核队列
    └─ 低置信度 (<70%) → 自动拒绝 + 人工处理
```

**数据库设计：**
```sql
CREATE TABLE review_queue (
    id UUID PRIMARY KEY,
    agent_name VARCHAR(50),      -- 哪个 Agent 的输出
    input_data JSONB,            -- 输入
    agent_output JSONB,          -- AI 输出
    confidence_score FLOAT,      -- 置信度
    status VARCHAR(20),          -- pending/approved/rejected
    reviewer_id UUID,            -- 审核人
    reviewed_at TIMESTAMP,
    feedback TEXT                -- 反馈
);
```

### 6. 成本意识 (Cost-Aware) 💰

**Token 就是钱，优化是必须的**

**成本优化策略：**

#### 6.1 模型分级使用

> **当前口径**：只接入 **DeepSeek V4.1 Flash**（通过 `langchain-deepseek` 官方集成），模型 id 由 `.env` 的 `DEFAULT_LLM_MODEL` 读取（默认 `deepseek-flash`），业务代码不写死模型名。
> 下面的「分级」是**预留扩展位**，不代表当前已接入多个模型。

```
简单任务 → 低 temperature + 小 max_tokens（同一模型，成本更低）
复杂任务 → 更高 max_tokens + 多步 Agent（同一模型，推理更充分）
```

```python
from app.core.config import settings


class AgentRouter:
    """根据任务复杂度选择模型

    模型 id 不写死在代码里，统一从配置读取（.env 的 DEFAULT_LLM_MODEL）。
    当前只有 DeepSeek V4.1 Flash 一个模型，因此各档位返回同一个 id；
    后续接入多模型时只改 model_map，不改业务代码。
    """

    def __init__(self, model_map=None):
        self.model_map = model_map or {
            "simple": settings.DEFAULT_LLM_MODEL,   # 默认 deepseek-flash
            "complex": settings.DEFAULT_LLM_MODEL,  # 预留：接入更强模型后替换
        }

    def route(self, task) -> str:
        complexity = self.estimate_complexity(task)

        if complexity < 0.3:
            return self.model_map["simple"]     # 简单任务
        elif complexity < 0.7:
            return self.model_map["simple"]     # 中等任务
        else:
            return self.model_map["complex"]    # 复杂任务
```

#### 6.2 缓存策略
```python
import hashlib
import json
from functools import lru_cache

class CachedAgent:
    def __init__(self, agent, redis_client):
        self.agent = agent
        self.cache = redis_client
    
    def invoke(self, input_data):
        # 计算输入哈希
        cache_key = hashlib.md5(
            json.dumps(input_data, sort_keys=True).encode()
        ).hexdigest()
        
        # 检查缓存
        if cached := self.cache.get(cache_key):
            return json.loads(cached)
        
        # 调用 Agent
        result = self.agent.invoke(input_data)
        
        # 写入缓存（24小时）
        self.cache.setex(cache_key, 86400, json.dumps(result))
        
        return result
```

#### 6.4 成本监控
```python
from app.core.config import settings


class CostTracker:
    """实时成本追踪

    单价不写死在代码里：金额一律按「token 用量 × 实际模型单价」现算，
    单价从配置/价格表读取（DeepSeek 官方单价，见 04-development/03-成本管理.md）。
    """

    # 结构：{"<model_id>": {"input": <每 1K tokens 单价>, "output": <每 1K tokens 单价>}}
    PRICING = {}  # 待按 DeepSeek 官方单价填入（不写死美元数字）

    def __init__(self, db, pricing=None):
        self.db = db
        self.pricing = pricing or self.PRICING

    def calc_cost(self, model, input_tokens, output_tokens):
        price = self.pricing[model]  # 未配置单价时直接 KeyError，避免静默算成 0
        return (
            input_tokens / 1000 * price["input"] +
            output_tokens / 1000 * price["output"]
        )

    def track(self, model, input_tokens, output_tokens):
        cost = self.calc_cost(model, input_tokens, output_tokens)

        # 记录到数据库（cost_tracking 表）
        self.db.insert_cost_record(
            service="deepseek",
            model=model,
            input_tokens=input_tokens,
            output_tokens=output_tokens,
            total_cost=cost,
        )

        # 实时预警（阈值来自配置：DAILY_COST_LIMIT）
        if self.get_daily_cost() > settings.DAILY_COST_LIMIT:
            self.alert("成本超限")
```

#### 7.2 数据脱敏
```python
import re

class DataMasker:
    """敏感信息脱敏"""
    
    PATTERNS = {
        "phone": r"1[3-9]\d{9}",
        "email": r"[\w\.-]+@[\w\.-]+\.\w+",
        "id_card": r"\d{17}[\dXx]",
        "bank_card": r"\d{16,19}"
    }
    
    def mask(self, text: str) -> str:
        for key, pattern in self.PATTERNS.items():
            text = re.sub(
                pattern,
                lambda m: m.group()[:3] + "***" + m.group()[-2:],
                text
            )
        return text

# 在 AI 处理前脱敏
masked_data = masker.mask(original_data)
result = agent.invoke(masked_data)
```

```python
class OutputValidator:
    """验证 AI 输出，防止泄露敏感信息"""
    
    def validate(self, output: str) -> tuple[bool, str]:
        # 1. 检查是否包含训练数据
        if self.contains_memorized_data(output):
            return False, "输出包含训练数据"
        
        # 2. 检查是否泄露用户隐私
        if self.contains_pii(output):
            return False, "输出包含个人隐私信息"
        
        # 3. 检查是否有害内容
        if self.is_harmful(output):
            return False, "输出包含有害内容"
        
        return True, "OK"
```

```python
import hashlib


class ABTestingAgent:
    """支持 A/B 测试的 Agent"""

    def __init__(self):
        self.variants = {
            "A": Agent(prompt="prompts/v1.txt"),  # 原版本
            "B": Agent(prompt="prompts/v2.txt")   # 新版本
        }
        self.traffic_split = 0.5  # 50/50 分流

    @staticmethod
    def bucket_of(user_id: str) -> int:
        """按 user_id 稳定分桶（跨进程一致；不要用内置 hash()，它受 PYTHONHASHSEED 影响）"""
        return int(hashlib.md5(user_id.encode()).hexdigest(), 16) % 100

    def invoke(self, input_data, user_id):
        # 根据 user_id 一致性分流
        variant = "B" if self.bucket_of(user_id) < 50 else "A"

        result = self.variants[variant].invoke(input_data)

        # 记录用于分析
        self.log_experiment(user_id, variant, result)

        return result
```

### LangGraph 工作流编排

**AI Insight Hub 的核心是多 Agent 协作**

```python
from typing import TypedDict

from langgraph.graph import StateGraph

# 定义状态
class ProcessState(TypedDict):
    data_source_id: str
    raw_data: dict
    cleaned_data: dict
    evaluation_result: dict
    knowledge: dict
    report: dict
    status: str

# 构建工作流
workflow = StateGraph(ProcessState)

# 添加节点（Agent）
workflow.add_node("clean", cleaning_agent.run)
workflow.add_node("evaluate", evaluation_agent.run)
workflow.add_node("manual_review_queue", enqueue_manual_review)
workflow.add_node("extract", extraction_agent.run)
workflow.add_node("report", report_agent.run)

# 定义边（流程）：evaluate 的出口交给条件边，不要再加静态边，否则路由冲突
workflow.add_edge("clean", "evaluate")
workflow.add_edge("extract", "report")

# 条件分支
def should_manual_review(state):
    if state["evaluation_result"]["confidence"] < 0.7:
        return "manual_review"
    return "extract"

workflow.add_conditional_edges(
    "evaluate",
    should_manual_review,
    {
        "extract": "extract",
        "manual_review": "manual_review_queue"
    }
)

# 编译
app = workflow.compile()
```

## 🎊 总结

### 核心理念

1. **Agent-First** - AI Agent 是核心，不是辅助
2. **Streaming** - 流式输出，提升体验
3. **Observable** - 可观测性，AI 不是黑盒
4. **HITL** - 人类审核，保证质量
5. **Cost-Aware** - 成本意识，Token 就是钱
6. **Secure** - 安全第一，保护隐私
7. **Iterative** - 持续迭代，数据驱动

### 关键区别

**传统 Web 应用开发 vs AI 应用开发**

| 维度 | 传统开发 | AI 应用开发 |
|------|----------|-------------|
| **核心** | 业务逻辑 | AI Agent |
| **确定性** | 确定 | 概率性 |
| **测试** | 单元测试 | Prompt 测试 + 单元测试 |
| **优化** | 代码优化 | Prompt 优化 + 模型选择 |
| **成本** | 服务器成本 | Token 成本 |
| **监控** | 日志 + 指标 | LLM 追踪 + 行为监控 |
| **迭代** | 版本发布 | 持续优化（Prompt/模型） |
