## 2. 高优先级问题（P0，必须修完才能开工）

> 标记说明：✅ = 本次已亲自复核（有原文或实测证据）；🔍 = 审查员报告、建议动手前再确认一次。

### P0-1 ✅ 向量维度自相矛盾：库表 1536 维 vs 嵌入模型 384 维

| 位置 | 内容 |
|---|---|
| `03-architecture/03-数据库设计.md:371`、`:495`、`:406` | `embedding VECTOR(1536)`、注释 `'文本向量表示（1536 维）'` |
| `03-architecture/01-系统架构.md:226` | `embedding VECTOR(1536), -- 向量（用于相似度检索）` |
| `03-architecture/02-Agent详细设计.md:736` | `SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2')` |
| `04-development/02-技术栈详细说明.md:717` | 同上模型 |

**影响**：MiniLM 输出 **384 维**，写入 `VECTOR(1536)` 列直接报错，知识库写入功能无法工作。**建议**：统一到 384 维（免费、离线），并同步注释与索引参数。

### P0-2 ✅ `audit_logs` 分区表主键缺分区键，PostgreSQL 会拒绝建表

`03-architecture/03-数据库设计.md:712` + `:731`

```sql
id BIGSERIAL PRIMARY KEY,          -- 主键只含 id
...
) PARTITION BY RANGE (created_at); -- 却按 created_at 分区
```

**影响**：PG 要求分区表的唯一约束必须包含全部分区键，此表**建不出来**。同文档 `raw_data`/`cleaned_data` 的写法是对的（复合主键），此处不一致。**建议**：改为 `PRIMARY KEY (id, created_at)`。

### P0-3 ✅ 全文检索依赖 zhparser，但 docker-compose 用的镜像里没有这个扩展

`03-architecture/03-数据库设计.md:796-797`、`:402`、`:521`：

```sql
CREATE EXTENSION zhparser;
CREATE TEXT SEARCH CONFIGURATION chinese (PARSER = zhparser);
...
USING GIN (to_tsvector('chinese', user_message || ' ' || ai_response));
```

而 `docker-compose.yml:6` 用的是 `pgvector/pgvector:pg14`（官方镜像，**不含 zhparser**，需自行编译安装）。`03-数据库设计.md:1123` 自己也把「安装扩展」列为待办。

**影响**：Alembic 迁移与建索引全部失败。**建议**：自建镜像预装 zhparser，或 MVP 先用 `pg_trgm`/`simple` 配置降级，并把扩展清单写进 `init_db.sql`。

### P0-4 ✅ docker-compose 挂载了一个不存在的 SQL 文件

`docker-compose.yml:16`：

```yaml
- ./backend/scripts/init_db.sql:/docker-entrypoint-initdb.d/init_db.sql
```

`backend/scripts/` 目录与 `init_db.sql` 均**不存在**。

**影响**：Docker 会把该路径建成空目录，初始化脚本静默失效（`CREATE EXTENSION vector` 等都不会执行）。**建议**：创建该文件（内容至少含 `CREATE EXTENSION IF NOT EXISTS vector;`）。
