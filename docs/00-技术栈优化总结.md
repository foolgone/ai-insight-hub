## ✅ 优化理由

### 1. **部署简化**
- ❌ 优化前：需要部署 4 个数据服务
- ✅ 优化后：只需部署 3 个数据服务
- **减少 25% 的基础设施**

### 2. **维护成本降低**
- ❌ 优化前：需要维护 PostgreSQL + ChromaDB 两套数据库
- ✅ 优化后：只维护 PostgreSQL 一套
- **减少 50% 的维护工作**

### 3. **事务一致性**
- ❌ 优化前：跨数据库操作，无法保证 ACID
- ✅ 优化后：单数据库事务，完全 ACID
- **数据一致性更强**

### 4. **查询性能**
- ❌ 优化前：需要应用层关联 PostgreSQL 和 ChromaDB 的数据
- ✅ 优化后：直接 SQL JOIN，性能更好
- **减少网络往返**

### 5. **数据量适配**
- 项目预估：~50,000 FAQ + 部分对话向量
- pgvector 性能：轻松支持 100万+ 向量
- **完全满足需求**

## 🔧 技术实现

### PostgreSQL + pgvector 配置

**1. 安装扩展**
```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

**2. 创建向量列**
```sql
CREATE TABLE knowledge_base (
    id UUID PRIMARY KEY,
    question TEXT NOT NULL,
    answer TEXT NOT NULL,
    embedding VECTOR(1536),  -- OpenAI ada-002 维度
    ...
);
```

**3. 创建向量索引**
```sql
-- IVFFlat 索引（推荐，适合大规模）
CREATE INDEX idx_kb_embedding ON knowledge_base 
    USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);

-- HNSW 索引（更快，但占用更多内存）
CREATE INDEX idx_kb_embedding_hnsw ON knowledge_base 
    USING hnsw (embedding vector_cosine_ops);
```

**4. 相似度搜索**
```sql
-- 余弦相似度搜索
SELECT question, answer,
       1 - (embedding <=> :query_embedding) AS similarity
FROM knowledge_base
ORDER BY embedding <=> :query_embedding
LIMIT 10;
```

## 🚀 迁移步骤

如果未来需要从 ChromaDB 迁移到 pgvector：

**1. 导出 ChromaDB 数据**
```python
collection = client.get_collection("knowledge_base")
data = collection.get(include=["documents", "embeddings", "metadatas"])
```

**2. 导入到 PostgreSQL**
```python
for i in range(len(data['ids'])):
    await db.execute(
        """
        INSERT INTO knowledge_base (id, question, answer, embedding)
        VALUES (:id, :question, :answer, :embedding)
        """,
        {
            "id": data['ids'][i],
            "question": data['documents'][i],
            "answer": data['metadatas'][i]['answer'],
            "embedding": data['embeddings'][i]
        }
    )
```

**3. 创建索引**
```sql
CREATE INDEX idx_kb_embedding ON knowledge_base 
    USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);
```

## 🎯 何时需要 ChromaDB？

**只在以下情况考虑 ChromaDB**：

1. ✅ 向量数据量 > **1000万**
2. ✅ 需要独立的向量搜索服务
3. ✅ 需要多模态向量（图片、音频等）
4. ✅ 需要 ChromaDB 特有功能

**AI Insight Hub 不需要**：
- ❌ 向量数据量：~50K FAQ（很小）
- ❌ 不需要独立服务
- ❌ 只有文本向量
- ❌ pgvector 完全够用

## 💡 最佳实践

### 1. **向量维度选择**
```python
# OpenAI ada-002
embedding = VECTOR(1536)

# Sentence Transformers (推荐，免费)
# paraphrase-multilingual-MiniLM-L12-v2
embedding = VECTOR(384)
```

### 2. **索引选择**
```sql
-- 数据量 < 10万：HNSW（最快）
CREATE INDEX USING hnsw (embedding vector_cosine_ops);

-- 数据量 > 10万：IVFFlat（平衡）
CREATE INDEX USING ivfflat (embedding vector_cosine_ops)
    WITH (lists = 100);
```

### 3. **查询优化**
```sql
-- 设置 ivfflat 探测列表数（影响精度和速度）
SET ivfflat.probes = 10;  -- 默认 1，越大越精确但越慢

-- 相似度搜索
SELECT * FROM knowledge_base
ORDER BY embedding <=> :query_embedding
LIMIT 10;
```
