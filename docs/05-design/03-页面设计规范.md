# 页面设计规范

**文档版本**: v1.1  
**创建时间**: 2026-10-24  
**最后更新**: 2026-10-25  
**作者**: AI Insight Hub 团队  
**状态**: ✅ 已定稿

> **v1.1 修订（2026-10-25）**：按产品需求（`01-requirements/03-场景梳理.md` S1/S5：数据源=文件导入、报告=4 类分析报告按需生成）与已上线后端 API 修正过度设计：
> 1. **数据源**：删除「平台店铺接入（淘宝/京东/拼多多 + API 密钥 + 测试连接 + 立即同步）」，改为「基本信息 + 上传文件」；状态按 `status`（active/archived/processing/error）表达，进度由 `statistics` 派生（API 不返回 `workflow_status`）。
> 2. **报告中心**：删除「日报/周报/月报/自定义」Tab 与 PDF iframe 预览，改为按 `report_type` 4 类（质量/知识/洞察/综合）的**按需分析报告**，格式 markdown/excel。
> 3. **知识库**：删除「导入」与虚构的「相似度/来源」字段呈现，改为「提取知识」入口 + FAQ 实际字段（question/answer/category/tags/confidence/quality_score/source）。
> 4. **登录/Header/清洗**：删除 SSO、注册、找回密码、全局搜索、通知入口；删除清洗「暂停/下载/日志」与「清洗前后预览」等后端无对应能力的交互。
> 5. **质量/报告细节**：质量 4 档分布改为「按最近 100 条评估列表统计」（`summary` 不返回 count）；评估详情去掉 API 不返回的「改进建议」，补「对话原文」；报告生成第 3 步改为 `include_charts`/`include_recommendations` 选项。
> 详见 §2.1/§3.1/§3.2/§3.3/§3.4/§3.5/§3.6/§3.7。

### 2.2 Sidebar（侧边栏）

#### 视觉规范
- **宽度**: 240px（展开），64px（折叠）
- **背景**: `gray-50`（浅色），`gray-900`（深色）

#### 菜单结构
```

📂 数据源管理

#### 菜单项规范
- **高度**: 48px
- **图标**: 20px，左侧对齐，距左边距 16px
- **文本**: 14px，距图标 12px

  - 左侧 3px 蓝色竖条
  - 背景 `bg-primary-50`（浅色），`bg-gray-800`（深色）

### 组件清单
1. **页面标题 + 新建按钮**
   - 新建按钮: `variant="primary"`，右侧固定

2. **筛选栏**
   - 搜索框: 320px，占位符 "搜索数据源名称"
   - 类型筛选: 下拉选择（全部/客服对话/销售/支持/其他，对应 `data_sources.type`）
   - 状态筛选: 下拉选择（全部/处理中/已就绪/已归档/异常，对应 `data_sources.status`）

3. **数据源卡片列表**
   - 组件: `DataSourceCard`
   - 布局: 单列，垂直堆叠
   - 内容:
     - 状态指示器（绿色=已就绪 `active`，黄色=处理中 `processing`，灰色=已归档 `archived`，红色=异常 `error`）
     - 数据源名称（`text-lg`，`font-semibold`）
     - 元信息（数据量、最后更新时间 `last_processed_at`/`updated_at`）
     - 操作菜单（右上角，下拉菜单）

4. **操作菜单**（点击展开）
   - 查看详情（进度按 `statistics` 派生：已上传 `total_records>0` → 已清洗 `cleaned_records>0` → 已评估 `quality_score_avg>0`；不展示 `workflow_status`）
   - 编辑信息
   - 上传数据
   - 开始清洗
   - 删除（红色，需二次确认）

5. **分页器**
   - 底部居中
   - 显示: 当前页/总页数

### 新建数据源流程
1. 点击 "新建数据源" → 打开 Drawer（右侧滑入）
2. **步骤 1**: 填写基本信息（名称（必填）、描述、类型（4 枚举））
3. **步骤 2**: 上传文件（CSV / JSON / XLSX / TXT，单文件 ≤ 50 MB）
4. **提交**: `POST /datasources`（`201`）→ `POST /datasources/{id}/upload`（`202 + task_id`）→ 跳转数据清洗页轮询任务
5. 异常提示：413 `FILE_TOO_LARGE` / 415 `FILE_FORMAT_INVALID` / 429 `DATASOURCE_QUOTA_EXCEEDED`

> **MVP 不做平台接入**：无「选择平台 / API 密钥 / 店铺 ID / 测试连接 / 立即同步」，数据一律通过文件导入（需求 S1、API §6.1）。

```

### 组件清单
1. **Tab 导航**
   - 全部、进行中、已完成、失败、已取消
   - 右侧显示数量徽章（如 "进行中 (3)"）

2. **任务表格**
   - 列: 任务名称、数据源、状态、进度、操作
   - 进度: 进度条 + 百分比 + 剩余时间
   - 状态徽章: 排队中（灰）、进行中（蓝）、已完成（绿）、失败（红）、已取消（灰）

3. **操作列**
   - 进行中: [取消]
   - 已完成: [查看结果]
   - 失败: [查看详情] [重试]
   - 已取消: [查看详情]

> 后端任务 5 态为 `pending/running/completed/failed/cancelled`；**无「暂停」「下载结果」「查看日志」端点**，操作列不提供这三项。

### 新建清洗任务流程
1. 点击 "新建清洗任务" → 打开 Modal（600px）
2. **步骤 1**: 选择数据源（默认当前数据源）
3. **步骤 2**: 选择清洗选项
   - 去重（`config.remove_duplicates`）
   - 文本标准化（`config.normalize_text`）
   - 敏感信息脱敏、格式标准化为固定管线，只读说明（无开关）
4. **步骤 3**: 确认启动 → `202 + task_id` → 轮询任务状态

> **MVP 不做「清洗前后对比预览」**（无预览端点）；清洗结果统一在清洗结果列表中查看。

### 组件清单
1. **整体质量概览卡片**

   - 饼图: 显示比例分布（统计口径同上：最近 100 条评估结果、按总分映射等级，界面标注样本范围）

2. **评估任务列表**
   - 组件: `Card` 列表
   - 内容:
     - 任务名称 + 评估对象

- 跳转到详情页 `/quality-assessment/:id`
- 显示:
  - 总分（0–100）
  - 各维度分数（**5 维**，维度定义见 `03-architecture/02-Agent详细设计.md`；用条形图展示）
  - 维度问题列表（`dimensions[dim].issues`，分类展示）
  - 对话原文（用评估项的 `data_id` 调 `GET /datasources/{id}/cleaned-data/{data_id}`）
  - 复核操作（`needs_review=true` 时：通过 / 驳回 / 修正分数，调用 `POST /datasources/{id}/analysis/quality/{result_id}/review`）

> 评估接口**不返回** `suggestions`（改进建议）与 `dialogue_id`，页面不展示改进建议；等级由总分按 90/75/60 前端计算。

### 组件清单
1. **操作栏**
   - 提取知识: 触发 `POST /datasources/{id}/extract-knowledge`（`202` 后轮询，`task_type=extract`），参数 `min_frequency`（默认 3）/ `similarity_threshold`（默认 0.85）/ `max_faq_count`（默认 100）
   - 导出: 前端把当前筛选结果生成 CSV（无后端导出端点）
   - 新建条目: 打开 Drawer

2. **筛选栏**
   - 搜索框: 走 `GET .../knowledge/search`（标题 + 答案，返回相似度）
   - 分类筛选: 下拉（对应 `category`；后端无标签过滤参数）
   - 排序: 最新、频次（对应 `sort=-created_at` / `sort=-frequency`）

3. **知识条目卡片**
   - 组件: `KnowledgeEntryCard`
   - 布局: 单列，垂直堆叠
   - 内容:
     - 问题（带图标）
     - 分类 + 标签（最多显示 3 个，超出显示 +N）
     - 答案预览（最多 2 行，超出显示省略号）
     - 元信息（来源 seed/manual/extracted、置信度、质量分、创建时间；**相似度仅在搜索结果中显示**）
     - 操作按钮

### 新建/编辑条目（Drawer）
- **字段**:
  - 问题（必填，`question`）
  - 答案（必填，`answer`，Textarea + Markdown 预览）
  - 分类（`category`）
  - 标签（多选，可新建，`tags`）
- **说明**: 无「来源」可填字段（由后端置 `manual`）；答案预览为只读渲染，不引入富文本编辑器
- **预览**: 右侧实时预览 Markdown 渲染结果（禁原始 HTML）

## 3.7 报告中心（/reports）

> **产品口径**：报告是「对某个数据源一次分析结果的总结」，**按需生成**、随该数据源的分析结果更新，**不是周期性日报/周报/月报**（无定时调度）。模板固定 4 套，对应 `report_type`；每份报告归属一个数据源（需求 S5、API §9）。
> **命名说明**：需求文档第 4 类「运营数据报告」中的解决率/转人工率等指标**当前后端未采集**；`comprehensive` 实际产出「质量+知识库+洞察」综合报告，因此 MVP 显示「综合分析报告」。运营指标报告列入 Phase 2，不以改文案代替功能。

### 布局
```
┌────────────────────────────────────────────────────┐
│ 📄 报告中心                        [+ 生成新报告]   │
├────────────────────────────────────────────────────┤
│                                                    │
│  [全部] [质量评估] [知识库] [洞察分析] [综合分析]  │
│                                                    │
│  ┌─────────┬─────────┬─────────┬─────────┐        │
│  │ 📊 质量 │ 📚 知识 │ 🎯 洞察 │ 📋 综合 │        │
│  │ 客服1月 │ 客服1月 │ 客服1月 │ 客服1月 │        │
│  │10-24 完成│10-24 完成│10-24 生成中│10-24 失败│      │
│  │ [下载]  │ [下载]  │ [---]   │ [重试]  │        │
│  └─────────┴─────────┴─────────┴─────────┘        │
│                                                    │
│  (网格布局，1/2/3/4 列自适应)                       │
└────────────────────────────────────────────────────┘
```

### 组件清单
1. **Tab 导航**
   - 全部 / 质量评估 / 知识库 / 洞察分析 / 综合分析（对应 `report_type` = quality/knowledge/insight/comprehensive）

2. **报告卡片网格**
   - 组件: `ReportPreview`
   - 布局: `sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4`（`<sm` 1 列）
   - 内容:
     - 类型图标 + 类型徽章（替代缩略图：后端不提供 PDF/图片渲染）
     - 报告标题
     - 生成时间 + 状态徽章（生成中/已完成/失败）
     - 下载按钮（仅已完成可点）

3. **报告详情**（点击卡片）
   - Modal（`lg`/`xl`，移动端全屏）
   - Markdown 报告：Markdown 渲染预览（禁用原始 HTML）
   - Excel 报告：元信息 + 下载（无在线表格预览）
   - 元信息：类型、格式、生成耗时、下载次数、关联数据源
   - 操作：下载 / 删除（`204` 后刷新列表）

### 生成新报告（Modal）
- **步骤 1**: 选择报告类型（AI 质量报告 / 知识库健康报告 / 客户洞察报告 / 综合分析报告）
- **步骤 2**: 选择数据范围（当前数据源 + 日期范围）
- **步骤 3**: 报告选项（是否包含图表 `include_charts` / 是否包含改进建议 `include_recommendations`）
- **步骤 4**: 生成（`202 + task_id` → 轮询，显示进度条）

> 格式仅 Markdown / Excel（PDF 列入后续版本）；生成是一次性异步任务，**没有日报/周报/月报模板与定时生成入口**。

## 四、响应式设计规范

### 4.1 桌面端（≥ 1280px）
- Sidebar 固定展开
- 内容区最大宽度 1600px，居中显示
- 卡片/表格使用完整布局

### 4.2 平板端（`md`–`lg`，768–1279px）
- Sidebar 可折叠（64px）
- 统计卡片：`md`（768–1023px）**2 列**；`lg`（1024–1279px）**4 列**
- 图表：`md` 1 列；`lg` 2 列

### 4.3 移动端（< `md`，< 768px）
- Sidebar 改为抽屉（点击汉堡菜单打开）
- 统计卡片 1 列（`sm` 640–767px 为 2 列）
- 图表 1 列
- 表格改为卡片列表
- 操作按钮改为 Icon Only

> 三档列数的**唯一定义**在 `04-响应式设计规范.md` 1.3；本节仅做页面级复述，若两处不一致以 04 号文档为准。

## 五、交互规范

### 5.1 加载状态
- **全页加载**: 显示 Spinner + "加载中..."
- **局部加载**: 显示 Skeleton（3 行）
- **按钮加载**: 按钮内 Spinner + "处理中..."

### 5.2 错误处理
- **网络错误**: Toast 提示 "网络连接失败，请重试"
- **服务器错误**: Toast 提示具体错误信息
- **表单验证**: 输入框底部显示红色错误文本

### 5.3 成功反馈
- **操作成功**: Toast 提示 "操作成功"
- **保存成功**: Toast 提示 "保存成功" + 自动关闭 Modal/Drawer

### 5.4 确认对话框
- **删除操作**: Popconfirm，标题 "确认删除？"，描述 "此操作不可恢复"
- **取消操作**: Modal，标题 "确认取消？"，描述 "未保存的内容将丢失"
